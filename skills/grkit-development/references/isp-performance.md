# ISP 色彩与拍摄性能契约

适用：普通滤镜新增／迭代、LUT 拟合、快照与缓存、Still／JPEG 接入、即时回放／相册／连拍优化。用户要求是原厂正片／负片同档流畅；不得把取景预览、离线模型或截图当作保存照片的性能证据。

## 数据流与所有权

GR III 2.10 已验收的任务入口为 `0x5351ea9c(owner, recipe)`：recipe 在 r1；原厂构造 `recipe+0x3b0+24*kind` 的消息和 `recipe+0x5f0+32*kind` 的元数据后才投递。冻结本张状态必须先于投递。`0x5351ae44` 所属流程回收旧缓冲、预留下一张，不是这条处理任务入口。地址仅适用于官方 RTOS SHA-256 `8a4eafcad2716e0b21e9909264e1242e534f0e39e05cba82a53546ceb4070b67`；其他版本／机型重新证明调用关系。

1. 使用本张曝光元数据选择胶卷，逐 recipe 冻结完整状态与 sequence；后续任务复用同一快照，之后的 UI 换卷／参数提交不能重定向排队照片。
2. UI 安全生命周期完成存档读取／校验后发布 owner 缓存。拍摄任务只读稳定缓存，禁止文件系统、分配、锁或等待。关闭 Live Make／取景色彩时仍保留拍摄缓存、owner 空间与发布；同步核验 HDF 尾部偏移，禁止重叠。
3. Still Make 对本张 frame 写入 ISP 参数，完成标记必须由真实执行产生并绑定 recipe、SI、tone、sequence、完整有效状态。不得用全局 last-selected、常量完成 mask 或跳过校验伪装加速。
4. JPEG 接入只对未由 ISP 完成的已授权空间／印字阶段处理，不能重复调色。普通卷关闭所有附加效果时不访问主图／预览像素、缓存维护、临时整图内存或存储服务。

3D LUT 的 ISP 拟合在离线／构建阶段完成，保留源 LUT、拟合器、参数／曲线与记录版本的哈希。拟合误差与实机颜色确认独立记录；不得每帧解析 LUT、现场拟合或把静默 CPU 回退当作兼容。历史自定义 LUT 未迁移时如实标记，不能宣称已全面 ISP 化。无 SD settings owner 的直接研究构建须由已证明的调用者显式提供快照，不能假设自动缓存存在。

当前可复用入口：`tests/test_gr3_film_pipeline_current.py`、`tests/test_gr3_isp_sd_compatibility.py`、`tests/test_gr3_view_recovery.py`、`tests/test_gr3_debug.py`。先核对它们是否仍覆盖当前 ABI 和最终交付包；文件名存在不等于执行通过。

日志诊断先匹配 build_id 和 CRC，再关联本张 `capture.settings.source`、`capture.native.completed`、`capture.cpu.residual`、阶段时间和 JPEG／保存边界。`source=4` 表示使用冻结快照；普通关闭效果时应有真实 native color 完成且 CPU residual=0。环形日志缺事件不能证明未执行。区分 CPU 调色、编码等待、保存等待和显示恢复；没有证据不归咎于 SD、机型或 ISP。

## 发布门槛

普通胶卷触发整图 CPU 调色、缺失本张快照／完成交接、关闭预览导致缓存缺失、即时回放无效果、长相册等待或持续连拍黑屏，任一项都是性能回归。保留保护性回退，修复正常路径；不得删除检查或篡改完成标志让用例变绿。

合并以最新线上 main 为底，检查累计差异和每个既有能力；重建验收配置并核对 BIN／源指纹。仅文档、版本说明等无行为变化可继续既有验收；原生行为或构建配置变化须重新交付候选并验证。全库既有失败如实做基线对照，不改无关断言掩盖失败。具体发布顺序遵守 `release-workflow.md`。

验收依据：2026-10-26 用户确认 GR III 2.10 RC2 修复通过，BIN SHA-256 `8346ff292a57727eb57d2d6fad919d330848ad9a37117284f5396919fdbf6992`，build_id `0c9a0164`。此前日志证实 5219 缺快照、native mask=0，CPU 色彩18.823秒；此数值是故障样本，不是修复后速度。未提供修复后计时，不虚构毫秒指标。
