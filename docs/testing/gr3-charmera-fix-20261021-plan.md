# Charmera 三项修复与发布

用户要求修复颜色可读性、胶卷库空白和实时取景，并于本轮明确授权修复后直接发布（覆盖技能默认的等待实机验收门槛）。无相机连接，不声称 camera_passed。

| 功能 | 原行为/根因 | 目标 | 验证入口 | 迁移 |
|---|---|---|---|---|
| 颜色 | R/Y/B/G + 颗粒 OFF 刻度 | 彩色且具名的四色值和四色刻度 | 原厂 ARM 详细页、最终图标回读 | 不改变 0..3 存档 |
| 胶卷库 | id<=288 过滤289 | 名称、卡片及分配失败小图均展示 | ARM settings_view | 历史编号不变 |
| 取景 | native look 排除289 | 缓存提交后按四色更新 ISP；切出不累积 | 原厂 Live Make + packer | 不访问 RAW/live 像素，不新增 I/O |
| JPEG | 既有 Charmera CPU 二值调色 | 保持原输出，预览不能设置已完成标志 | recipe/捕获/host | 保留逐张快照 |
| 其他 | 五槽、SD、HDF、按键、原厂及其他机型 | 保持既有行为 | Node 全套及相关 Python/ARM | 不重排目录、不改记录版本 |

执行：先写复现测试并确认失败，再逐项修复；沿已有候选构建器生成 C03、校验产物与指纹；更新 changelog，仅整合发布依赖的现有改动，普通推送 main/develop，跟踪 Actions 与公网健康检查。既有 A/B 实机故障保持单独标记。
