# 800T FN 崩溃与效果回退修复

上一版存在实际缺陷。此次先保存上传输入，再对照官方 GR III 2.10 的指令与执行路径定位；没有用“上次测试通过”否定实机反馈。

## 输入核验与日志结论

上传 `fwdc239b.bin` 的 SHA256 为 `dcf953ec70c0f92b89ec3a0850d4ec72755ed62840e8b647978ff0c53c7d520d`，与上一轮交付完全相同。两份 CP 日志 CRC 有效，build ID 为 `dc764af9`，合并后 14 条记录，对应两次完整的 6000×4000 处理。

两张均为第一槽 800T，使用默认配置：强度 3、范围 3、阈值 5、颗粒 1、柔光 0；处理返回 0，暂存空间 562,500 字节。说明不是刷错版本、关闭光晕或拍照路径未执行。返回 0 只证明函数完成，不能证明视觉效果正确。此次没有菜单通道日志，FN 崩溃位置由上传固件的离线 ARM 执行和官方代码对照定位。

## FN 黑屏：两处具体缺陷

1. 官方函数 `0x531afa10` 与 `0x531aff84` 使用 `LR=12` 计算三组参数表的索引。新增 BL 跳转覆写了 LR，随后计算到错误地址。此前测试只覆盖 setting=0，乘数为零时错误被隐藏。实际 FN 初始化会遍历全部 3×12 组合。
2. 详细页构造时先使用原厂默认 tone11，只分配最多 11 行，随后才读取实际胶卷。800T 动态追加五项后需要最多 16 行，原先没有预留容量。

修复恢复两处索引路径所需的 LR，构造阶段独立预留 16 行；显示仍使用原厂实际数量，非 800T 的额外行按原厂逻辑隐藏。保留所有五项滑杆、原厂确认/退出与原有负片颗粒。

直接使用三个版本的 RTOS 字节执行同一个原厂初始化函数 `0x531afbe0`，仅替代外部界面/存储服务：

| 输入 | 结果 |
|---|---|
| 官方固件 | 正常返回，分配 11 行 |
| 此次上传固件 | 在 `0x531afa30` 读取 `0xf41717ac`，触发未映射内存错误 |
| 修复固件代码 | 正常返回，分配 16 行 |

还覆盖实际整行分发函数 `0x531aff84`：原厂 tone11 与五个承载槽 × 三组参数，共 18 种组合。原厂槽不出现新增行，五个承载槽各显示五项，栈恢复正常。证据在 `constructor-comparison.json` 和详细菜单测试输出中。外部服务仍有替代，因此不把这些结果称为真实相机 FN 操作已通过。

## 红晕与青色

上一版对高光面积做平均并多次归一化模糊，较宽光晕在最后的整数合成中会归零。新增 6000×4000 场景回归：16×16、亮度 235 的灯，灯外 16 像素处，上一版红色分量差为 0；修复后要求至少 3 级。保留细光源近场扩散，对较宽扩散单独增加 16 倍曝光贡献。此调整作用于所有尺寸，不只是“修复舍入”；默认强度仍为 3，可在机内调低。白色灯芯保护、弱高光不产生密集红点、阈值单调、九档范围和边界检查继续验证。

上一版青色参数在亮度 64 的中性灰上只有 Cb=129、Cr=127，几乎中性。新版恢复明显的青色中间调，减弱对红色光源的染色，白色核心保持中性。它是针对用户要求的青色扫描风格，不是以真实 Fuji 扫描器数据标定的仿真。

参考 [CineStill 官方说明](https://cinestillfilm.com/blogs/news/cinestill-film-stock-primer) 的高光红晕特征及 [官方冷色平衡说明](https://help.cinestillfilm.com/hc/en-us/articles/360028874452-What-type-of-light-is-CineStill-800Tungsten-made-for)。扫描校色、光源与曝光都会影响成片，不能把某个固定青色量称为唯一正确的 800T。

包内对比图由同一张已有图片分别通过上一版与修复版 C 代码生成，两者同为 3/3/5、颗粒与柔光关闭。它用于看清算法差别，不是本次相机的实拍验证。

## 使用与优先验收

仅适用于 GR III 2.10；不适用于 IIIx、IV 或 GR DIGITAL III。保留上传包的五槽胶卷、日期时间戳、画幅、水平仪及负片颗粒，RAW 降噪为 stock。设置命名空间保持 M10V3，不重置已有机内调节值。修改的公共版本号仍为 2.10，使用随包 SHA256 和日志 build ID 区分构建。

备份照片并充满电，把本包 `fwdc239b.bin` 放到 SD 根目录，按住 MENU 开机进入更新，完成前不要断电。操作参照 [Ricoh 官方更新说明](https://www.ricoh-imaging.co.jp/english/support/digital/gr3_s.html)。本包未验证硬件恢复流程。

1. 先在图像控制列表按 FN，验证能进入、返回，再反复进入三次；分别检查 800T 和原厂负片。
2. 800T 详细页应有 Halation Gain、Halation Spread、Highlight Gate、Grain、Soft Diffusion；分别调一档，退出、切槽、重启后检查保存。沿用原厂即时滑杆回调：退出不会撤销已成功保存的值。
3. 固定曝光、白平衡、构图，先设 Grain/Soft 为 Off，比较强度 0/3/6 的 JPEG；范围 3、阈值 5。检查白灯周边红晕、较大亮窗和弱反光，避免只比较缩略图。再比较各档范围与阈值。
4. JPEG 与 RAW+JPEG 各拍一组，检查文件完整、保存速度和连拍响应。当前只处理保存的静态 JPEG，不承诺实时取景或机内 RAW 再开发效果。
5. 每组测试后备份四份日志；环形日志会覆盖较早内容。回传原 JPEG、五项参数和四个日志，才能进一步定位真实像素域和物理交互。

本版新增 `capture.highlight.energy`：记录进入处理前的最大高光能量、超过阈值的像素数、图像像素数与阈值。它能区分“画面没有超过阈值”和“已有高光源但扩散不足”。为取得完整统计，调试版额外扫描一次原始 JPEG 平面，其相机耗时待实测。`capture.settings` 的 renderer_revision 应为 3。

运行 `python3 read_gr3_debug_log.py M10VCP0.BIN M10VCP1.BIN M10VMN0.BIN M10VMN1.BIN > decoded.json` 可解析日志。菜单文件若不存在，只传实际存在的文件。
