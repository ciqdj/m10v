# GR III 800T 实施与验证记录

2026-10-13。平台已支持生成 **离线核验的实验候选固件**，包含 800T 色彩、弱／强两档原生红晕和可选原有时间戳。用户已验证首版可以更新、启动与 RAW＋JPEG 拍摄，但未观察到红晕；本次修正版尚待实机复拍。

## 使用

1. 在 GR III 工作区导入精确官方 `fwdc239b.bin`（2.10）。
2. 打开「实验性」，选择弱／强档和时间戳，点击「检查 800T 机内方案」。
3. 点击「下载 800T 实验固件」。构建完成且独立核验通过后，下载 BIN 与 `m10v-800t-build.json`。
4. 将生成的文件提供给本会话进行再次分析。平台在 `builds/gr3-800t-output/` 按候选 SHA 保存预检、预期字节与回执，可核对从浏览器下载的实际包。

网页滑块只调浏览器参考图，机内为两档固定参数。800T 占用 Bleach Bypass 色彩槽，其余四个胶片槽使用现有默认胶片。色彩从 V3 500T 作实验性冷色暗部调整，没有从未配对扫描反推出精确乳剂响应。

## 原厂契约

完整 RTOS SHA 与逐指令前像由 `gr3-800t-evidence.mjs` 和 `gr3-800t-contract.json` 锁定。

- 原厂 CPU/VFP/NEON 的像素转换、格式填充和低级描述符适配实际执行，零 stub：format1/addressMode2 是 CbCr 422，uint8、128 中性值。
- 原厂 planner 实际执行 15 种模式，允许的 0/1/5/6/7/8/12 均有 BackResize → 等待 → JPEG → 等待 → 清理。生产者等待硬件完成后才返回；scheduler 等 callback 再推进。
- 主 JPEG 与额外 JPEG/DNG 预览可能共享已经开发的像素。因此它们可能同步出现效果；CFA 编码输入区间由原厂 RAW consumer 契约确定，适配器强制不重叠。
- 原厂启动页表将 0x540b6000..0x540bc000 恒等映射为可执行只读代码。容器扩展位于原有分区容量内；首版实际更新与启动已由用户验证；修正版运行仍待复拍。

## 原生接入

核心 2376 字节；适配器 1652 字节。扩展 wrapper 位于 0x540bb000，适配器 0x540bb040，核心 0x540bb6b8；全部位于同一 4096 字节页。原捕获 trampoline 保存寄存器/APSR，完成红晕后调用可选时间戳，再恢复状态并尾调用原厂 send。

适配层强制 recipe/type/拓扑、允许模式、主 JPEG 请求、目标 tone、format/addressMode、尺寸/步幅、独立 Y/C 平面范围与互不重叠、CFA 与元数据隔离。临时区由原厂分配器获取，与图像/CFA/元数据/预览全范围检查不重叠。分别对 Y/C 输入与输出的实际触及范围 `(height-1)*stride+width` 调用原厂缓存维护，返回前释放；无效流程和分配失败跳过效果。

## 独立验证

Python 构建器保持本地兼容运行时散列锁；不修改缓存或以输入字段解除证据约束。Node 独立解码全部容器帧、外层/解码校验、节次序和非目标节；第二套 Node 编译器从可信固定模板、所选色彩数据及已审查代码锁独立重建允许字节，核验全部 RTOS/ICONBIN 和扩展页。构建器与 expectation 同时写错跳转也会被拒绝。

## 2026-10-13 红晕被跳过修复

用户确认首版为 RAW＋JPEG、已选择 800T、场景有明显高光。原厂 JPEG Setup6 位于 RAW Setup7 之前；旧适配器却要求随后才填充的 `R+a54`、`R+a80` 已有效，导致提前返回。现从当前有效的 `R+60` 与 status 的尺寸指针界定 CFA 区间，继续逐平面检查不重叠。

执行锁定的原厂构造和分配 ARM 指令发现：6000×4000、stride6016 的 Y/C 平面之间有 866368 字节间隙，旧版连续平面假设不成立；描述符 `+1c` 由 `strb/ldrb` 操作，是字节枚举，其后三字节是 padding，旧版按整字比较也会误拒绝。修复保留平面边界、CFA、元数据及临时区隔离。原生红晕核心和两档阈值没有改变。

复现脚本：`scripts/analyze_gr3_800t_capture_allocation.py`；ARM 对照结果：`builds/gr3-800t-debug/old-versus-fixed-arm.json`。四种失败条件下旧版均没有像素写入，修正版均进入处理。测试明确 stub 分配、缓存、硬件调用，不能替代实机验证。

色彩额外暗部偏移从 `[-0.04,0.008,0.035]` 收敛到 `[-0.015,0,0.012]`，减少附加青色偏移；不是经过实拍配对标定的精确乳剂响应。

修正版强档、无时间戳候选：`builds/gr3-800t-fix-v2/fwdc239b-800t-v2.bin`，31164344 字节，SHA-256 `d219c4d649dd4f30807d5bbc19321ce6e3cfbf42f1507c62a7295fe76921baf5`。Node 测试 83 项通过、1 项既有兼容性样本跳过；原生/ARM 38 项通过。完整包独立回读、配置绑定、全部预期代码及非目标节检查通过。新版需要用户刷入后用相同高光场景复拍，并分别检查 JPG、DNG CFA 和内嵌预览。

## 2026-10-13 按胶卷样片修正青色暗部与溢光

用户的新明确要求是更明显的高光红晕、青色暗部和更强整体饱和度。上一轮纯桌面原型偏深蓝，且8位扩散会丢失微弱点光源尾部。本轮完整图使用即将写入固件的 Q13 矩阵、Bleach 实际33点曲线、Q512后矩阵，再运行实际原生C核心；RGB↔YCbCr422仍是近似转换，不能冒充相机RAW/ISP或胶卷配对标定。

资料依据：

- [CineStill：What is Halation](https://help.cinestillfilm.com/hc/en-us/articles/360029185291-What-is-Halation)：强光从胶片背面反射形成溢光，清晰聚焦光源更明显。
- [CineStill：适用光线](https://help.cinestillfilm.com/hc/en-us/articles/360028874452-What-type-of-light-is-CineStill-800Tungsten-made-for)：冷色平衡与混合光源产生不同外观；青色暗部在这里是按用户样片和偏好确定的目标，不宣称是所有800T扫描的固定颜色。
- [Dehancer Halation](https://www.dehancer.com/learn/article/halation)：分别控制光源下限、背景显现、扩散、增益及红橙比例；对比边缘和镜面高光也可能产生红晕。
- [spektrafilm / 原agx-emulsion](https://github.com/andreavolpato/spektrafilm)：完整光谱模拟从线性输入，经负片、印相、扫描多个阶段。本次没有移植其光谱模型或代码，不宣称便携固件等价于完整物理模拟。

固件色彩方案保留V3-500T基础矩阵，使用轻度S曲线与按输入亮度变化的曲线差 `[-0.035,0.065,-0.012]`；后矩阵叠加1.28倍饱和度并修正量化后的每行之和为512，近白高光保持小色差，暗部更青。实际Bleach33点曲线测试检查中性暗部的G/B接近、G大于R及暖冷彩色测试样本的颜色跨度至少增加15%。该跨度不是物理色度饱和度测量。

强档原生核心加入四邻域光源对比检查，非极亮点需要至少64级局部对比，248及以上极亮点使用16级；源阈值216，原弱档210不变。强档背景衰减由平方改为线性，红色系数256，亮度抬升为红色增量的3/4，Cb下降为1/4，使红晕在中间亮度背景上更显著且有橙色分量。三轮模糊替代此前四轮，保留集中边缘；弱档像素计算保持原样。局部亮度规则无法语义区分灯与反光车身，部分高对比镜面反光仍会产生效果。

回归用例：同一灯芯/150背景的Cr增量15→37、亮度抬升27；235均匀亮面指定边缘Cr增量66→0；高光中心仍不写入。CFA/元数据隔离与平台原始契约未更改。`-Os`下核心2372字节，仍在0x540bb6b8..0x540bc000内，余4字节。原生/ARM41项通过；新的邻域读取及编译优化的实机耗时需要复拍观察。

## 2026-10-13 降低绿色偏移、核对倒影误触发

用户指出新版过绿，水面倒影不应出现样片中没有的红晕。色彩绿通道暗部偏移+.065收回到+.025，红/蓝偏移为-.020/+.006，后矩阵饱和度1.28收回到1.16，保持蓝青分离。实际Bleach33点曲线中性暗部测试改为G高于R至少9级、B高于G8..18级，避免重绿色且仍区别于纯深蓝。

诊断桥梁上一版色彩结果的Y：标注水面区域最大247，场景最大249。实验将所有红晕源限到Y>=248并使用固定种子能排掉该照片的水面，但目视检查同时误伤了真实暖色路灯，且存在247→248突变。该实验未采用，原生核心/锁/测试恢复到上一已验证版本；没有输出或开放含该失败规则的新固件。

新的目标预览 `builds/gr3-800t-balanced-study/bridge/800t-strong-water-excluded-prototype.png` 使用新固件色彩表、原核心加手动水面多边形标注，区域内回退到色彩单独输出。深水区域y>=1500的红晕改动像素为0。`water-review-mask.png`和`water-review.json`明确记录人工标注。它是外观目标，并不证明机内具备自动水面识别。亮度门槛无法语义识别所有水面或反射；自动倒影排除仍待设计与验证。街景蓝青色彩参考在同study目录，核心保持原状。
