## 修复与兼容

- `m10v_settings_view_draw` 原先把自定义 ID 强制画成 33 号 800T；现在从每个槽位快照或目录的绝对 index 读取名称，生成前五个字母/数字与稳定配色，卡片明确标记 LUT，下方保留全名。
- `m10v_menu_name` 的内建资源映射不支持自定义 ID；发布分支新增 991..995 五个独立槽位名称资源。两个原厂 getter 的自定义分支保存原寄存器，在当前 getter 的栈中放置 UTF-16 descriptor，消费完成后由原厂 FP epilogue 恢复 SP，避免跨调用共享指针。
- 原图标路径直接使用 `670 + custom ID`，落入动态卡片资源或越界；现在使用独立 754 号 40px LUT 图标，并在导出时独立检查 descriptor、像素和源码哈希。分配失败也使用该安全图标。
- 原卡片 749..753、内建图标 671..748、胶卷 ID、FILMS.M10、双 bank 快照、五槽状态与 LUT 数值保持不变。
- 本地 r2 测试包含当时工作区的 A/B 依赖，因此与本次隔离发布的二进制不同；发布分支不包含 A/B，名称资源编号由 1007..1011 调整为 991..995，并重新执行发布检查。此前包的测试结果不冒充本次候选的证据。

目标实现为 GR III 2.10 与其现有 IIIx 适配消费者；GR IV 不使用本段菜单实现，保留其部署构建及型号校验。生产构建/HTTP 检查不证明 LCD 显示、机身栈余量、响应时间或照片效果；仍需相机实测。

发布经既有 GitHub Actions → 受限 SSH → 宝塔链路执行，必须核验当前 SHA 的 `DEPLOY_OK ... service=active` 和公网首页、GR III 工作台、guide、changelog。失败使用既有回滚链路，不修改 root SSH 授权或降低三机型构建保护。
