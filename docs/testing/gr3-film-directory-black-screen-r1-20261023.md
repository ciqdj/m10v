## 离线根因证据

在哈希固定的GR III2.10原厂RTOS上执行真实构造器和文字setter，首次绘制分类页可稳定复现非法读取：

`m10v_settings_view_draw` → 分类计数VALUE控件（原厂type17，vtable `0x53c0a378`）→ 错误调用ASCII文字setter `0x53390ef8`（应供type0、vtable `0x53c09e80`）→ 原厂字符串例程 `0x5313fcf4` 读取 `0x01000000`，Unicorn报 `UC_ERR_READ_UNMAPPED`。

这条PC/地址来自离线原厂代码执行，不是从相机日志读取；它与首次进入立即黑屏的实机触发点一致。不得据此声称新BIN已在相机上通过。

## 修复

- 分类计数使用type17对应的资源文字setter `0x53396f80`，不再把该对象当成ASCII字符串控件。
- 新增1137..1167的数字资源“0”..“30”，覆盖分类最大14项和旧卷清理最大10项；严格资源数量351→382同步回读，没有放宽地址、字节或大小校验。
- 五组、30款、名称、LUT、稳定ID、十槽存档和拍摄参数保持本次目录版本。
- 发布预检查另发现GR IV的显式省略API表没有包含GR III新增的两个目录接口，已补齐省略声明；未给GR IV启用GR III路径，完整GR IV构建与独立封包回读通过。
