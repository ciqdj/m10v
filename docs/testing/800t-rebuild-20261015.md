# GR III 800T 重做版：刷入与实机测试

本包为 GR III 2.10 修改固件，包含新版 800T 和五项原厂详细页调节。已完成的软件验证见同包 `验证结果.md`；尚未在真实相机刷入、操作或拍摄，不能把离线 ARM 测试视为实机通过，也不能声称已经完成与胶卷扫描件的定量色彩匹配。仅供 GR III；不适用于 GR IIIx、GR IV 或 GR DIGITAL III。

## 本次变化

- 800T 从着色前的 JPEG 高光提取能量，使用近场与较宽扩散叠加，去掉旧的光源形状筛选和最大值放大。白色灯芯受保护，周边形成红橙色扩散。
- 强度、范围、阈值独立可调；颗粒和柔光不会反过来产生光晕种子。已裁切到白色的 JPEG 高光没有 RAW 曝光信息，不能恢复真实胶片曝光量。
- 五个槽位中，任何设置为 800T 的槽位都增加五项详细调节；其它胶卷保留原本详细页。保留原包画幅、水平仪、负片颗粒扩展；RAW 降噪保持原厂配置。
- 新版记录使用 `M10V3A.bin / M10V3B.bin` 的原厂 AppData 存储接口，与旧记录隔离。旧版开启的光晕迁移为 3/3/5，原本关闭的仍关闭；胶卷、颗粒、柔光和时间戳保留。旧文件不覆盖。第一次实际调节后才写入新版记录，单纯浏览不写设置。
- 包内默认五槽为 33/64/54/56/37；第一槽 800T，强度 3、范围 3、阈值 5、颗粒 Weak、柔光 Off；日期时间戳保持上传包的日期模式。若相机已有有效记录，已保存/迁移的配置优先。

## 刷入

1. 备份 SD 卡照片、原来的固件与四个日志文件。确认型号为 GR III，电池充满。
2. 把本包顶层的 `fwdc239b.bin` 放到 SD 卡根目录，文件名保持不变；不要复制 `evidence` 内的中间构建文件用于更新。
3. 关机后插入卡，按住 MENU 开机，进入固件更新画面，选择 Execute 并按 OK。出现 Update completed 后关机。更新过程中不要关机或拔卡。这一步按 [Ricoh 官方 GR III 更新流程](https://www.ricoh-imaging.co.jp/english/support/digital/gr3_s.html) 操作。
4. 正常开机后检查图像控制和详细页。修改包公共版本号仍是 2.10，不能只靠版本号区别；包内 SHA256 和拍摄日志 build ID 用于识别此次构建。

若更新菜单拒绝文件或相机无法正常开机，不要把未验证的强制升级、降级或恢复方式当作可用方案。本包不包含经过实机验证的救砖流程。原始上传固件仍保留在原位置，未被改写。

## 五项机内调节

在“图像控制”中选中 800T，沿原来进入负片详细调节的操作进入详细页，滚动到新增的五行。选择一行后使用原厂滑杆调节，按原厂返回/确认操作退出。新增行的英文标题与中文含义如下。

| 画面标题 | 参数 | 范围与含义 | 初始建议 |
|---|---|---|---|
| Halation Gain | 光晕强度 | 0–8；0 关闭红晕 | 3 |
| Halation Spread | 扩散范围 | 0–8；0 仍有最小近场扩散，8 最宽 | 3 |
| Highlight Gate | 高光阈值 | 0–8；越高越少高光参与 | 5 |
| Grain | 颗粒 | Off / Weak / Mid / High | Weak |
| Soft Diffusion | 柔光 | Off / Weak / Mid / High | Off |

原厂滑杆回调是即时生效的，调节时即尝试保存。返回/取消只退出界面，不撤销已经成功的调节。重置会一次重置这五项到固件内该槽默认值。

保存或回读失败会提示错误并恢复当前显示值；若发生“写入成功、随即回读失败”的存储故障，实际落盘结果可能不确定，应重新进入页面或重启后核对。离线测试没有证明所有物理 SD 故障都能回滚。不要在写入时主动拔卡测试。

## 实机验收顺序

先完成菜单和保存测试，再比较照片。每组拍完及时备份四个日志，环形日志只保留最近记录。

1. **五项独立性：** 每项分别改变一档、退出并重新进入；其余四项不应跟随变化。切换其它槽再切回，关机重启，再次检查数值。
2. **五槽与负片：** 把第二或第五槽临时换成 800T，确认同样出现五行并独立保存。切回其它胶卷后应恢复原详细项目；原负片颗粒的调节仍能工作。
3. **拍摄基准：** 三脚架、固定手动曝光和白平衡、相同构图与 JPEG 设置，关闭自动 ISO。先把颗粒、柔光设为 Off。比较保存的 JPEG 原文件，而非取景画面或截图。本次未接入实时取景与机内 RAW 再开发。
4. **光晕强度：** 范围 3、阈值 5，依次拍强度 0/3/6。选择暗背景中的白灯、小路灯、大面积亮窗与红色灯牌。0 应无新增红晕，3/6 应逐渐增加，白灯中心不应变成一整块红色；大光源不能因面积而被直接排除。
5. **阈值：** 强度 3、范围 3，拍阈值 0/5/8。高阈值应减少中等亮物体、反光纹理的红晕；若灯已被曝光压暗至阈值以下，不应凭“它是灯”强行加红。
6. **范围：** 强度 6、阈值 5，拍范围 0/4/8，100% 查看灯周边扩散宽度。保持曝光一致；能量扩散更宽时局部峰值可能下降，并非所有位置都应更红。
7. **密集误触发：** 拍暗部细纹理、细网格、树叶、密集弱反光和皮肤，比较 Gain 0 与 3。没有强高光的地方不应出现密集红点。再轻微平移构图，孤立灯光不应因落在采样网格不同位置而突然消失。
8. **颗粒与柔光：** 强度固定 3，分别比较 Grain Off/High、Soft Off/High。颗粒应改变纹理；柔光应增加柔和亮度扩散，不能把暗部噪点变成红晕源。再以 Gain 0 检查柔光独立生效。
9. **完整路径：** JPEG 和 RAW+JPEG 各拍至少五张，包含最高分辨率和一个较小尺寸；检查照片完整、文件可读、保存耗时、连续拍摄响应和重启。RAW 文件不应被此 JPEG 效果改写。相机耗时尚未实测，请记录每张保存时间。

建议回传：每组 JPEG 原文件、对应 RAW（若有）、参数记录、详细页照片/短视频、四个 SD 日志。保留曝光元数据，不经过社交软件压缩。若出现死机或写入失败，记录最后一次操作、分辨率、五项参数与存储卡型号。

## 日志判读

本包开启调试，会向 SD 根目录写 `M10VMN0.BIN / M10VMN1.BIN / M10VCP0.BIN / M10VCP1.BIN`。拍照日志与菜单日志分开，每通道最多 63 条；拍摄次数过多会覆盖较早内容。完整参数随每张处理记录，不靠“菜单看起来变了”推断生效。

可在电脑执行：

```sh
python3 read_gr3_debug_log.py M10VMN0.BIN M10VMN1.BIN M10VCP0.BIN M10VCP1.BIN > decoded-log.json
```

- `detail.change`：项目、旧值、新值、槽位和存储返回值；项目 18–22 依次为五项参数。
- `capture.settings`：实际用于该张 JPEG 的 gain/spread/threshold/grain/soft、配置序列号和渲染版本。
- `capture.settings.source`：记录来自新版存储、默认值、旧版 64 字节记录迁移或更早记录迁移。改变参数后拍摄应显示新版存储来源；重启后应保持。
- `capture.render.after`：处理返回值；0 表示处理函数成功，不代表画质已经实机验收。
