# GR3 5207 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans inline. Track verification and constraints here; the user has instructed execution of the reviewed proposal.

**Goal:** Add a distinct M10V精选 5207 with source-traceable colour and independent grain/light leak controls, producing an audited experimental GR3 firmware.

**Architecture:** Offline reference generation from the reviewed 5207 spectral data; bounded fixed-point camera colour and texture kernels; versioned five-slot configuration shared by web, camera menu and capture. Existing IDs and effects remain compatible.

**Tech Stack:** Python/NumPy reference, freestanding C/ARM, Node ES modules and browser JavaScript.

**Spec:** `docs/research/gr3-5207-proposal-2026-10-16.md`

## Global Constraints

- New stable ID 66, key m10v-5207; keep IDs 1–65 unchanged.
- Traditional 35mm 5207 / ECN-2 / neutral scan; no 2383 baked into the default.
- 5207 has no halation processing or controls. Default leak/soft off; grain weak. Preserve source attribution and reproducibility.
- Fixed 512 KiB module mapping, protected RAW and original encoder chain.
- Physical camera calibration and film match cannot be claimed from host or emulation tests.

## Review Focus

- Old valid journals retain film IDs and controls through migration and failed writes.
- New ID must never index old tables or inherit the previous film's strong effects.
- Invalid buffers and insufficient memory must leave pixels unchanged.
- Full-frame seeds, orientation and resolution changes must not create repeated/blocky textures.
- Build fingerprints, resource pointers, catalog count and table payload must agree.
