# GR III 800T Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** 实现两档 800T 红晕内核、精确固件证据检查与实验构建入口，仅在相机格式和调用链证据充分时开放 BIN 导出。

**Architecture:** 新增独立 C 整数内核与 ARM 验证器，Node 配置和构建门槛沿用现有 GR III 流程。相机布局证明与主机参考模型分开，未经证明的格式不能进入固件写入器。

**Tech Stack:** Node.js 原生测试，Python 3.12、Capstone/Unicorn，本机 clang ARM 目标；不修改散列锁定的 GRLife 缓存。

**Spec:** `docs/superpowers/specs/2026-10-12-m10v-gr3-800t-design.md`

## Global Constraints

- 仅接受官方 SHA-256 `d6a3c9c288d784080e7b283222ecdd8752adfeed6faa36dab44f73115354bfd4`，输出内部版本 2.10。
- `weak`、`strong` 两档；目标槽位 800T；保护 CFA 像素；红晕先于时间戳。
- 图像格式、RAW 分流、可执行范围及独立回读缺一项时不能导出 BIN。
- 保留所有现有未跟踪文件；新工作使用独立分支；不提交照片、固件和第三方缓存。

## Review Focus

- 可见宽不等于步幅：写入只覆盖有效像素，尾部和邻区守卫保持原值（任务2）。
- 分配失败或参数非法：无部分写入，完整返回原厂处理（任务2、3）。
- 新功能与时间戳竞争入口：只有单一适配器，原厂调用次数和寄存器保留（任务3、4）。
- RAW+JPEG 的 DNG 预览复用：保护 CFA 与预览处理分开报告（任务1、4）。
- 用户修改参数或绕过浏览器：服务端重新核验基线、能力和接受配置散列（任务4、5）。
