# 800T 重建方案：高光能量扩散与原厂详细设置

日期：2026-10-15。状态：待用户评审，尚未实现、尚未生成新固件。

## 用户目标

完全替换现有 800T 红晕方案，纠正该泛红处漏检、非目标处密集泛红的问题。保留光晕强度、扩散范围、高光阈值、颗粒、柔光五项调节，且在相机内按原厂负片颗粒的详细设置交互调节。以 CineStill 800T 为目标，不将其他去碳电影卷或风格化 LUT 自动当作等价标定。

## 当前源码的问题

`m10v_library_render` 先用风格曲线改变 Y/CbCr，再调用 halation，导致风格调色改变光源资格。`halation_core.c` 对最高 384×256 网格 max pooling，用点状局部峰和极亮窄条特例筛源，随后按连通面积排除，再对模糊结果做根号放大。6000×4000 时单格对应 16×16 像素，微小高光面积被放大；形状分类与栅格相位可能同时造成漏检和误检。

源码中 g8/t0/profile3 对应较强处理，而本批日志恰为该组设置。日志不含完整像素与逐阶段遮罩，不能据此宣称所有视觉症状的唯一根因已证实。

负片颗粒参考实现仅开放原厂已有 item15；800T 的另外四项没有等价原厂处理器，不能只改条目数就声称完成。当前原生库菜单属于独立私有子菜单，不等同于原厂详细设置。

## 参考与准确性边界

1. [CineStill 官方胶卷说明](https://cinestillfilm.com/blogs/news/cinestill-film-stock-primer)：800T 为 3200K 平衡彩色负片，聚焦的过曝高光周围可见红晕，日光下可通过滤镜或扫描调整色温。
2. [Dehancer 红晕技术说明](https://blog.dehancer.com/articles/halation/)：从曝光、空间散射及红/绿层响应解释红橙晕；强调光源与背景、扩散及 bloom 可分别调节。用于物理方向参考，不复制其专有算法。
3. [PictureFX 800T v1 作者页](https://picturefx.itch.io/picturefx-cinestill-800t-v10)及[v2 作者说明](https://marcrphoto.wordpress.com/2025/02/28/picturefx-cinestill-800t-v2-0-lut/)：不同版本有不同色温/滤镜假设，不能混成一个“官方色彩”。本次查阅作者说明，未下载、测量或集成 LUT 数据。

逐像素 LUT 不含邻域信息，不能单独产生空间红晕。官网描述和第三方 LUT 不是光谱、曝光、冲扫的标定数据；没有同场景数字原图与明确冲扫条件的胶片参考，不能承诺精确胶片复刻。8bit JPEG 前 YCbCr 已经过 ISP，不能恢复截断高光能量；新版定位为受约束的近似模拟，实机成片为最终验收依据。

## 方案选择

- 继续追加灯形状规则：不采用。会继续把高光类型与几何形状绑定，边界条件不断增长。
- **推荐：原始处理缓冲上的高光能量 + 多尺度扩散 + 独立色彩/颗粒/柔光。** 保留已验证的 JPEG 捕获边界及内存保护，替换光晕核心与处理顺序。
- 在 RAW/ISP 更早的线性域实现完整曝光模型：理论信息更充分，但当前没有该挂钩的布局、同步和处理契约证明。本次不冒险写 CFA，也不假称现有 YCbCr 是场景线性数据。

## 新处理链

输入契约核验 → 在风格调色前提取高光能量 → 有限半径扩散 → 合成红橙晕和独立柔光 → 800T 色彩响应 → 颗粒 → 原有时间戳。

1. 将输入 YCbCr 在明确矩阵/范围假设下转换到工作 RGB；传递函数未有实机证据前，所有逆变换标为近似。用单调查表和定点计算保持 ARM 成本可控。
2. 源能量采用软拐点超阈值响应。亮度为主、红通道为辅助连续权重，避免单一 Y 阈值漏掉亮红灯，也避免把所有有红色的物体当作光源。废除 Cr<112 的硬类别排除、点灯/窄条判断和连通面积硬删除。
3. 以面积覆盖和能量积分降采样，保留细小光源的贡献但不将一个亮点变成整个网格满亮。近场保留较细分辨率，远场使用粗分辨率；双线性重建避免格块和逐格跳变。
4. 使用归一化近场和远场散射核，半径按画面尺寸统一；红通道远场比绿色更宽更弱，生成内侧偏橙、外侧偏红的渐变。去除根号抬升弱尾部。
5. 用平滑接收权重控制亮部中心可见染色，保留光源核心；没有合格源时红晕严格为零。均匀亮区不能被整块染红；亮区与暗区边缘允许合理、连续、弱的扩散，不使用“天空永不红”作为伪物理要求。
6. 柔光独立控制近中性色光散射，不读取已添加的红晕作为新光源；颗粒在成像链末端合成，避免噪声变成红色散射种子。
7. 色彩响应独立标定，记录白平衡和输入假设；保留肤色与中性阶，不以全局青偏或强红偏冒充 800T。第三方 LUT 仅作对比参考；若实际集成，先确认输入域与许可。

具体核权重、阈值和默认强度须由参考样本拟合后固化；这里不编造已标定数字。首先产出可复现 host 参考实现及源遮罩/红晕/柔光单独可视化，再据此裁剪 ARM 实现。工作内存设上限并检查溢出、对齐、别名，不能为赶体积牺牲边界保护。

## 机内五项控制

当前槽位为 800T 时，在原厂图像控制详细页增加独立项目，沿用原厂选择、调整、确认、取消及返回的交互。不会占用原厂饱和度、色相、锐度。非 800T 槽位继续保留原厂条目含义。

|项目|范围|行为|
|---|---|---|
|光晕强度|0–8|0 关闭；只改变红晕能量|
|扩散范围|0–8|九档不同有效半径，不再九档压成五档|
|高光阈值|0–8|越大越只保留更强高光；软过渡|
|颗粒|关/弱/中/强|场景亮度相关、近零均值，和红晕独立|
|柔光|关/弱/中/强|独立中性散射，和红晕独立|

用原厂负片颗粒作为 UI 和生命周期参考；复核旧独立菜单的 count/list/value/setup/callback/reset/caption 接入点，与现原生库桥合并，不直接叠两套旧补丁。自定义条目必须按当前槽位 film ID 判断，而不是只认 tone18；五个承载槽均需覆盖。

私有参数由同一持久化 backend 拥有，菜单、网页默认和拍摄快照不得各存一份。原厂回调经逆向证实是即时生效：滑杆回调即写入，确认/取消只退出，不额外写入也不回滚已提交值；SD 失败明确反馈，不能假装保存。捕获线程每张读取一次稳定快照，不在像素循环读盘。重启、切槽、重置均需验证。旧 halo_profile 保留兼容迁移入口，映射到新版强度后不再作为第六项隐蔽乘数；迁移版本化并可诊断，避免旧 8/8/0/强档静默覆盖新默认。

## 验收与交付门槛

- 图像回归：点灯、横/竖/斜灯带、宽窗、彩灯、反光、白墙/天空、肤色、夜景细节；必须比较源遮罩、单独红晕、最终图，不能只看全图红通道总和。
- 栅格稳定性：同一图平移 1–16 像素后逆向对齐比较，禁止出现整片红晕消失；检查 6000×4000 与 3360×2240 的归一化半径。
- 参数：强度为 0 的红晕增量为零；九档半径有序；阈值升高不会增加源能量；颗粒/柔光可分别关闭；不要求非线性调色后每个 RGB 像素严格单调。
- 菜单：执行真实原厂 selector/setup/callback 链，验证五槽、进入、调节、确认、取消、重置、重启和失败路径；新增日志必须记录 item、旧/新值、槽位、保存结果及拍摄使用值。
- ARM：参考输出一致、越界/别名/对齐检查、寄存器/栈保持、无外部未解析依赖；记录运行耗时与峰值内存，实机未知的耗时不写成通过。
- 构建：从官方基线重建，结构校验、所有补丁精确回读、共享挂钩和资源冲突审计、保留已选扩展。原始上传文件不覆盖。
- 实机：新候选需 LCD 五项可达、确认保存、关机重启恢复，以及每次只改一项的同场景 JPEG/RAW+JPEG 对照。未完成前标记“待实机验证”，不得声称准确还原已完成。
