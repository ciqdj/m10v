# m10v GR III 三批固件扩展与流畅编辑设计

日期：2026-10-13。状态：用户以“执行”确认总体设计，进入实施计划审阅；本文不是功能实现或相机验收完成证明。

## 1. 用户目标与范围

用户要求完成上一轮提出的第一批、第二批、第三批扩展，仔细分析保证功能准确，并使 UI 操作丝滑流畅。“第二屏”按上下文理解为“第二批”。

范围包括负片颗粒、更多原厂名称/图标、逐胶片颗粒、12 色相分区、新增胶片槽位、机内 RAW 显影、独立参数保存、逐胶片柔光、已有 800T 组合、RAW 降噪和更多画幅。XMP 导入与 Street 关机图作为上一轮扩展列表的相邻需求列入独立交付项，不能在三批结束时默默遗漏。

只针对当前精确 GR III 2.10 官方源文件 SHA-256 `d6a3c9c288d784080e7b283222ecdd8752adfeed6faa36dab44f73115354bfd4`，当前目标机身为 Street Edition。不扩大到 GR IIIx/GR IV，不自动刷相机，不输出未经核验的候选。固件与图像仍在本机处理。

软件交付和相机验收是两个状态。完成要求是实际配置进入构建、独立回读与必要 ARM/算法验证通过、UI 可用；只有相机端记录才能把相应功能标为实机验证。无法取得必要证据的功能必须说明实际阻断项，不能用灰色按钮、浏览器特效或预设数据冒充完成。

## 2. 当前代码与证据复核

- `node/gr3-store-plan.mjs` 仅暴露 recipes/timestamp/aspect/film/level 五项，配方六槽，胶片必须选五款。`node/gr3-film-plan.mjs` 输出 films-v10 替换方案，没有质感或色相分区。
- 本地 GRLife 清单已包含逐胶片颗粒和柔光，在线 manifest 摘要与本地固定摘要相同。缺口是产品接口、组合处理和本项目独立验收，不能描述成必须更新运行时才能使用。
- `node/gr3-candidate-audit.mjs` 只接受 RTOS 正增长且只允许 RTOS/ICONBIN 改变；因此原地颗粒、RES 修改、其他布局不能直接通过当前验证器。必须按获准方案生成独立预期，不放宽成任意差异。
- `node/adapters/gr3/index.mjs` 仍报告通用适配器不支持裁切/关机/build，而专用服务已有候选路径。能力报告必须统一，避免相同功能在不同入口出现相反状态。
- `web/gr3/studio.js` 在胶片切换时重建整个功能列表、重新加载图像，并在主线程执行像素变换。自动保存同步写 localStorage，异步预检没有统一版本竞争处理。
- 当前 800T 代码已具有真实构建、静态契约、ARM 验证和独立回读；早期研究文档中的“没有候选/色度未知”不能继续当现状。当前核心 2372 字节，原区域余 4 字节；组合柔光必须重新分配代码和数据范围。
- 已核对官方负片菜单：`0x53B348BC` 指向 `0x53B3500C`，项目数为 9，尾部为 `00004f6e537461727400`。Darkslide 的 10 项颗粒方案前像匹配。
- 已核对 RAW NR 前像：`0x5343326C=0x02266001`、`0x53433284=0x02277001`、`0x53642AC4=0x13834018`。
- 新胶片效果阶段默认 `0x53513210=0xE3A03000`；只写颗粒值或文件标签不能证明颗粒、暗角和清晰度生效。
- gr-custom-tool HEAD `549591d`，Darkslide `9913169`，gr3-film-mods `04d5d5d`；后者公开构建器到 v16，v17–v33b 是研究记录。v32 有实机比例错误/闪烁，v33 尚无相机验收。

## 3. 选定结构与替代方案

推荐：保留旧五槽方案作为兼容模式，新增本项目的能力注册、规范化配置、补丁计划、扩展空间分配和独立验证层。GRLife 用于固定版本兼容构建；公开 GR III 代码用于可审计的数据/处理逻辑参考，最终由统一组合层确认改动范围与顺序。

替代一：直接串接各项目生成器。开发短，但代码洞、模式编号、菜单表、RES 路径和捕获入口容易互相覆盖，不能准确支持三批组合。

替代二：马上替换所有原有构建器。隔离更彻底，但现有配方、时间戳、水平仪与 800T 都要重新建立回归证据，交付成本高。采用渐进整合，并保留关闭新功能时的旧方案回归。

拆成四个可独立验收的子项目：A 原厂编辑与颗粒；B 胶片系统；C 空间效果/降噪/画幅；D XMP 与 Street 关机图。每个子项目有对应实施计划、验证记录和明确状态，统一 UI 随子项目交付。

## 4. 配置和组合契约

新增 `m10v-gr3-customization/v2` 的严格规范化配置，与 GRLife 私有 plan 分离。主要域为：

- `presets`：原厂身份、名称、图标、可支持的九项默认参数；名称/图标编辑不得隐含改色彩。
- `negativeGrainMenu`：布尔开关，只开放内置 Negative Film 的原厂颗粒项。
- `filmSystem`：`replace-five` 或 `append`；有稳定 ID 的胶片、顺序、颜色数据、图标、九项默认参数、颗粒、柔光、可选红晕。
- `rawNr`：`stock`、`off` 或 `threshold`，阈值以确认的原厂表索引映射；JPEG NR 独立保持原厂。
- `aspect`：受已核验能力表限制的比例与框线设置。
- `timestamp`、`level`：保留已有实际配置和行为。
- `shutdown`：独立资源与叠加层配置，不借用胶片名称空间。

未知字段、错误类型、非法模式、重复 ID、矩阵溢出或非法尺寸均拒绝。输入原包摘要、规范化配置摘要、构建器/依赖版本与证据摘要绑定到预检和构建回执；修改任意设置后不能下载旧结果作为新方案。

补丁计划包含原始前像、目标字节、所属功能、地址范围与容量。范围重叠必须由明确的共享模块合并，不能允许后写覆盖。扩展分配器检查 ARM 对齐、分支距离、执行映射、数据复制与所有者，不采用“全零就是安全代码洞”的假定。粒子、曲线、色相表、图标和菜单使用不同资源预算。

## 5. 子项目 A：第一批

### A1. 负片颗粒

开放原厂颗粒菜单，值由相机原厂逻辑保存和应用。菜单 9→10 与追加项的修改必须独立回读；关闭时不得保留残余补丁。与原厂名称/图标、旧五槽胶片、时间戳、画幅、水平仪、800T 分别测试组合。

### A2. 原厂名称与图标

参考 Darkslide 的真实限制：Standard 只开放图标；其他原厂槽按核验表开放名称和图标。Custom1/2 保留现有独立配方机制。部分名称扩容会使用其他语言空间，优先采用明确的新字符串资源和重定位；若保留上游空间复用方案，必须展示并验证受到影响的语言，不能静默改变其他语言。

文字、位图尺寸、透明边界、相机字库和字符长度按目标槽验证。Darkslide 图标内区与 m10v/GRLife 40×40 RGBA 不能当同一种文件直接互用；提供明确转换与生成后像素回读。

### A3. 每款胶片颗粒

界面提供关闭/弱/中/强。内部菜单档到存储档的映射为 0→0、弱→3、中→2、强→1，不能简单把 UI 数字写入原厂字段。质感跟随胶片稳定 ID，重新排槽时重算实际模式映射。

第一步为五替换槽构建时固定档；B 阶段扩展为新增槽位的相机内独立菜单与保存。共享 Vivid/Positive 分支必须只影响选定胶片，Positive 保持原厂。验证实际效果阶段输入和分派，不能只验证 ShootingInfo 中的值。

## 6. 子项目 B：第二批

### B1. MultiAxial 色相分区与拟合

支持 12 色相分区的实际原厂可表达矩阵，量化到公开代码要求的格式；行和、离对角量化与溢出边界必须严格检查。浏览器高级面板以色相区和效果控件表达，原始寄存器放诊断信息，普通用户无需接触地址。

拟合依次约束矩阵、曲线、后矩阵和色相区，提供肤色/灰阶优先及全色域均衡。评分分别标记模型误差、量化误差与相机实测误差，不宣传任意 LUT 精确复刻。色相预览与固件都消费同一规范化量化参数。

### B2. 新增胶片条目

保留全部原厂条目，新增模式采用专有 ID、名称、图标及完整消费者转换。容量由验证后的原厂数组、重定位表和已分配空间决定；第一版 UI 最多允许 6 个新增胶片，只有六槽最大组合证明通过才开放此上限，否则报告实际容量并阻断发布，不能降低数量后声称满足设计。

替换模式和追加模式互斥，不将五替换槽资源与追加条目随意叠加。旧五槽草稿迁移后仍为替换模式，不自动改变用户固件方案。

### B3. 机内 RAW 显影

新增胶片必须同时接入拍摄菜单、RAW 显影选项列表和容量、参数页、As Shot、MakerNote 写入/读回以及回放文字/图标。每个枚举转译做有效/无效边界探查，未知私有 ImageTone 不得造成数组越界。

首版 RAW 显影支持色彩、原生参数和已验证的颗粒。柔光与红晕首版仅限已经证明的拍摄 JPEG 路径；对应显影页面不能显示为可用。第三方软件可能无法识别私有标签，构建清单和导出方案保留 ID 对照。

### B4. 每款胶片独立保存与回退

为拍摄、Custom/U 场景及 RAW 显影建立独立参数拥有关系。存储文件包含 magic/schema/长度/胶片 ID 映射/校验，损坏、未知版本或移除胶片时回到合法原厂值。文件写出、备份、读入、重设、冷启动、取消编辑和批量同步都验证；不占用已有 APData 编号。

参考 FILMDATA 研究自行证明真实 FS 调用、写入顺序和失败行为；不凭模拟 FS 成功宣称断电保存可靠。返回原厂前需保证各设置拥有者不保存私有模式 ID，提供具体相机操作与检查记录。没有硬件自动回退能力，不作此承诺。

## 7. 子项目 C：第三批

### C1. 柔光、红晕和时间戳

柔光和红晕使用一个捕获适配器和一个布局/所有权守卫。明确顺序：原厂粒子效果（原厂已有路径）→柔光/红晕→时间戳→原厂 JPEG 提交。双空间效果都开启时先从效果前图像取得高光源信息，避免柔光把红晕种子放大；实现、预览与验证记录必须采用同一规则。

柔光关闭/弱/中/强与800T关闭/弱/强分别配置，初版构建固定，不擅自声称机内可调。组合需重定位到有足够空间的扩展布局；固定代码散列、栈、scratch 峰值与调用顺序。分配失败、尺寸/格式不符或隔离失败时保持原厂路径，不留下半处理像素。

只改允许的 JPEG 图像区，RAW CFA 与解释元数据受守卫保护；DNG 内嵌预览可能与拍摄 JPEG 共用，必须独立报告。亮度规则不能识别所有水面倒影，不新增未经证明的自动倒影排除声明。

### C2. RAW NR

先实现构建时配置：原厂、关闭、从经原厂表验证的 ISO 起启用。前端显示实际支持阈值，不接受任意数字暗中取整。两个机身变体表和备用捕获路径均检查；曝光、Live View、JPEG NR 不应因该开关被改动。

这项按设计会改变 RAW 像素，因此验证“空间效果不修改 CFA”时采用相同 NR 策略基线，不能把 RAW NR 作用与内存破坏混为一谈。机内菜单控制为后续独立需求，不复用上游已发现开机同步问题的 JPEG NR 菜单方案。

### C3. 更多画幅

保留当前已验证组合3:2/1:1/4:3/65:24。扩展5:4/16:9/2.39:1需要逐个完成菜单、主图大小、取景模式、框线、回放、RAW 显影、持久化与时间戳布局证明后开放；UI自定义输入仅接受核验列表，不承诺任意比例。

取景采用原厂已证明的传感器模式与蒙版/框线，不启用 GR III 上半配置的4:3/16:9驱动模式。没有相机端无闪烁记录时标为待实机验收。验证所有输出尺寸、35/50mm crop（适用时）、边缘框线与叠加层组合；不改变DNG有效窗口而声称RAW像素裁切。

## 8. 子项目 D：相邻扩展

XMP 只接收完整支持的 Look/Profile 内容，解析外部引用、蒙版等不支持内容并解释具体缺项；转换为GR III模型后使用B1拟合与评分。不能使用GR IV结果直接填GR III寄存器。优先纯本地转换，Lightroom实渲染不作为默认外部依赖。

Street关机图沿Collabo及Today叠加链验证，资源修改和用户更新器实际写入路径分别证明。保留目前候选的离线状态，不能凭RES替换通过就宣称相机显示替换图。前端提供裁切/压缩后的真实编码预览和目标容量；合作版处理不借用Darkslide保留合作图的通用方案。

## 9. UI与性能验收

保持现有本地工作台视觉体系，提供“原厂预设 / 胶片 / 质感 / 画幅 / 构建”明确入口。胶片列表、选中详情和图像预览使用稳定DOM节点，切换时保持滚动、焦点和展开状态；不再每次replaceChildren整页。

统一编辑状态包括schema/revision/dirty/任务ID；草稿迁移保留旧数据备份。保存合并300ms，pagehide完成最后快照；存储失败显示未保存状态。大图片/图标进入项目资产存储，localStorage仅保留轻量配置。撤销/重做使用编辑事务，滑杆一次拖动成为一步撤销。

预览转Web Worker：原图只解码一次，按原图摘要+量化配置+预览尺寸缓存。交互低分辨率预览、停止200ms后精细预览；任务带序号且只接收最新revision结果。rAF合并拖动，传输缓冲区避免主线程像素循环；无法使用Worker时降低预览分辨率并显示状态。

异步拟合、导入、预检和构建有状态、耗时、取消/放弃当前结果与重试，不显示伪进度。服务端任务取消需终止其专属worker/子进程并删除临时文件；不能只关闭UI而继续留下“已取消”任务。构建任务绑定不可变快照，编辑新方案不会污染正在构建的包。

验收使用本机Chromium、1280×800和较窄视口记录：控件即时反馈p95<100ms；拖动低清结果p95<150ms；连续拖动与切换测试无本应用同步计算导致的>50ms长任务；稳定后高质量结果<1s（固定620×413测试图）。记录机器/浏览器/图像尺寸与样本数量，不推断所有电脑达到同一指标。固件构建耗时单独记录，不要求在100ms内完成。

键盘导航、对比拖杆、焦点可见、错误就地说明、 reduced-motion 支持必须验收。频繁滑杆变化不刷屏ARIA通知。切换页面不强制滚动到固定300px；仅由明确导航和焦点恢复决定滚动。

## 10. 验证与交付标准

每个子项目按规范化输入→原字节断言→构建→独立解码→实际预期字节/参数→原厂回归→UI完整操作交付。独立验证不能只相信生成器自报的expected文件；从获准配置重新推导关键补丁、表、映射和代码散列。

允许RTOS零增长或增长、RES修改等必须按方案类别证明，不全局扩宽现有审计白名单。BOOTPARA/DRAMPARA/PARTPARA/M0/BOOT/CPU和更新器相关范围默认原样；每个变更分区和字节区间可解释。错误前像、重叠、溢出、损坏存储、无效枚举、陈旧配置与取消竞态有拒绝测试。

ARM/算法测试覆盖颗粒模式和效果门禁、12分区量化、所有新增胶片ID和RAW转换、最大容量、共享入口/寄存器/缓存、边界尺寸与分配失败。相机试拍另覆盖重启保存、RAW显影页、JPEG-only/RAW+JPEG、无高光/灯光/均匀亮面、保存耗时、画幅取景和恢复；缺记录时保留camera_tested=false。

最终交付逐项列出已实现、已离线核验、已实机核验或具体阻断，附实际测试计数、候选摘要和UI性能记录。不用总测试通过代替固件实机证明。

许可沿用各项目来源：GPL代码保留对应义务；色彩数据按各自CC BY-SA/CC BY-NC-SA来源标记，不把Classic Neg等受限数据统一当商业可用。原厂固件、抽出的GR IV数据和未获授权素材不纳入源码分发。

## 11. 审阅后的执行

先审阅本文的架构、范围与验收标准，再分别为A/B/C/D形成实施计划并选定执行方式。优先A，同时把统一配置/能力状态与流畅编辑基础铺好；B完成后C复用新的空间分配和胶片身份。不能把仅A完成作为用户三批任务完成。
