# GR III 800T 机内胶片与红晕设计

日期：2026-10-12。用户已确认本文的总体方向：800T 色彩基底、弱/强两档空间红晕、保留现有时间戳、保护 CFA 数据，以及证明和回读通过后开放实验固件导出。本文是待用户审阅的正式设计，尚不是实现完成证明。

## 目标与验收范围

在 m10v 现有 GR III 固件编辑流程中新增 800T，使相机按快门后保存的 JPEG 具有胶卷样本中的色彩和橙红色高光外溢。弱档参考 `800T胶卷实拍4.jpg` 的点灯红晕，强档参考 `800T胶卷实拍5.jpg` 的灯带外溢。高光核心保留，扩散优先显现在周围较暗区域；无强高光时不产生大面积红色染色。

沿用当前精确 GR III Street Edition 2.10 官方包 SHA-256：`d6a3c9c288d784080e7b283222ecdd8752adfeed6faa36dab44f73115354bfd4`。不扩展到其他固件、GR IIIx 或 GR IV。输出内部版本维持 2.10。

“保护 RAW”指不向 CFA 像素缓冲区及解释参数写入。DNG 中的全尺寸 JPEG 和小预览分别记录其处理行为；不能以整份 DNG 的哈希或预览颜色代替 RAW 数据检查。首版不要求取景预览和机内 RAW 再显影支持红晕。

原厂颗粒作为独立可选项，不能把颗粒或亮度柔光的成功视为红晕成功。首版重点为色彩与两档红晕，不能因颗粒的硬件验证未完成而扩大候选补丁范围。

## 当前证据与实现前置条件

详细证据见 `docs/research/gr3-800t-samples-2026-10-12.md` 和 `docs/research/gr3-800t-in-camera-plan.md`。

已有：精确官方/修改包身份；`0x535048E8` 的原始与修改 BL；现有适配器保留原厂调用；`JpegEncodeMacroProcess` 类型关联；低级描述符格式 1/2 对应 422/420；观察的创建路径包含亮度区和合并色度区；14 项原厂 ARM CPU 探查；原厂范围缓存维护函数链。

仍需取得以下可复核证据，不能以假定值替代：

- 合并色度区的 Cb/Cr 字节顺序、取值编码，以及横向采样和分配行跨度。
- 主图描述符从创建到 JPEG 硬件读取期间的所有权、生命周期和别名关系。
- JPEG-only、RAW+JPEG、DNG 预览及 RAW 写出路径的分流和限制条件。
- 注入代码的可执行映射、分区容量、寄存器约定、栈对齐、分支范围和缓存可见性。

条件未证明时，构建器返回具体缺项及地址证据，不产生可刷入 BIN。浏览器 RGBA 预览参数不得直接解释为相机内存配置。

## 架构和数据流

继续使用 m10v 本地 Node 服务、现有 GR III 项目配置、精确原包加载器和独立固件回读器。新增内容分为以下边界明确的模块：

1. **逆向证据配置**：记录精确固件身份、代码前像、已证实的图像格式、分流条件、原厂函数地址和可使用代码范围。每项绑定原字节与分析依据；未证实项保持构建阻断。
2. **800T 色彩基底**：使用现有自定义胶片矩阵/曲线机制，作为一个明确命名的实验 800T 预设。不声称仅凭本批不同场景照片能够精确恢复胶卷响应；记录选择和视觉标定过程。
3. **独立颜色/空间内核**：C 的有界整数实现及相应 ARM 产物，亮度高光掩码、缩小后的扩散场、暗部保护和色度红向写入可分别验证。不依赖浏览器或 GRLife 柔光 blob 的未解释布局。
4. **捕获适配器和补丁构建**：将新内核合并到现有单一捕获入口，保留时间戳和原厂调用。只启用选择 800T 的目标槽位，其他槽位执行原流程。保持调用者的寄存器、标志和原厂返回行为。
5. **独立验证**：回读新代码、配置、槽位数据、全部分区和容器校验；对原厂软件路径做 ARM 探查，对硬件/系统模型明确注明限制。
6. **产品入口**：沿用现有实验性面板，在官方包核验后选择 800T、弱/强红晕与时间戳组合，展示实际构建状态和下载。原有浏览器视觉参考继续标记其适用范围。

数据流：项目选择 → 验证官方身份与证据配置 → 生成色彩数据及内核参数 → 合并适配器 → 构建 → 独立回读 → 本地下载实验包。页面不自动写 SD 卡或连接相机。

## 两档红晕内核

强度预设为 `weak`、`strong`，导出后固定在固件中；首版不新增相机菜单。实际阈值、半径和色度增量通过样本与相机尺寸标定后锁定并记录。

处理使用已证实 JPEG 亮度掩码。缩小网格上的有限次滤波形成有界扩散，抑制亮点中心和低强度背景，再按实际采样格式回写色度。色度红向转换严格采用已证明的编码。必要时加入受控亮度增量，避免只改色度在极暗像素出现不自然色块。

从原始掩码计算扩散，避免输出再次进入掩码形成失控扩散。弱/强档共享格式检查和资源上限；强档不得解除上限。半径按图像尺寸缩放，不直接把缩图的像素半径套到 6000×4000。

临时内存使用原厂分配/释放接口并限定最大需求，复杂度须随像素或网格大小有明确上界。分配失败、格式不匹配、未知采样、尺寸/步幅非法或地址范围无效时跳过效果，恢复原厂链。任何写入都必须先完成完整跨度检查；不能已经部分改写后再发现参数非法。

## 现有功能兼容

800T 只占用现有五个胶片槽位中的一个，按现有冲突规则分配。时间戳不得被新 BL 覆盖；在扩散后绘制时间戳，避免把日期文字本身作为高光扩散源。原厂 JPEG 发送顺序和等待逻辑保留。

如果解码后的现有程序中 `+0x5000..+0x5FFF` 零区不满足代码容量或可执行证明，必须按已证实的扩展机制安排新程序；不得把“字节为空”视为可执行证明。GRLife 缓存和散列锁保持原有行为，新内核使用本项目自己的来源与验证清单。

## 校验和失败行为

每个覆盖点具备原字节前像，禁止将新补丁施加到任意用户修改包。构建从精确官方包重建已选功能；已有修改包用作兼容回归样本。

独立验证检查容器解码、分区大小与容量、版本、校验和、ARM 入口/跳转/代码散列、两档参数和所有非目标字节。报告列出实际允许改变的范围。不能仅依赖构建器自报成功。

固件导出能力只有在关键格式和分流证据已完整、内核/调用链验证通过、候选包独立回读通过时才开放。构建失败返回可定位错误；不生成或复用之前的候选包作为新结果。

## 验证计划

- 图像：点灯、长灯带、饱和红/蓝灯、非高光暗景、均匀白场；检查红晕位置、暗部保护、中心保留和两档差异。
- 内存：最小/常用/最大尺寸、可见宽与分配宽不同、边缘高光、空/短缓冲区、整数溢出、未知格式、分配失败；使用写入守卫确认仅目标图像区变化。
- ARM：将编译产物与主机整数参考逐像素比较，验证调用者寄存器/状态、栈、退出路径、缓存调用范围与次数。系统、ISP、JPEG 硬件模型明确分开记录。
- 构建：红晕关闭、弱、强及各档配时间戳；未选择 800T 的槽位保持原处理；验证错误基线和补丁前像不匹配时拒绝导出。
- 硬件：先以现有已运行固件建立拍照基线；候选通过离线检查后，记录启动、JPEG-only 与 RAW+JPEG、无高光对照、保存时间、原始 JPEG/DNG。实机验证由用户在相机上执行，不能把本地测试写成实机完成。

本批样本和探查只支持设计与基线，尚无新增内核的相机测试。实现交付必须分别报告“离线可构建/回读通过”和“实机效果/稳定性结果”。
