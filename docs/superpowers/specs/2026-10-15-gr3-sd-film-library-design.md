# GR III 自研 SD 胶卷库设计草案

日期：2026-10-15。状态：待设计确认，尚未实现或生成固件。

## 用户目标

m10v 平台可全选或多选任意数量的可用胶卷导出到 SD 卡；GR III 机内有胶卷库入口，可随时从卡上选卷替换最多五个活动影像风格槽。GRLife 仅参考公开交互，不导入它的代码、运行时、文件格式、签发服务或素材。谨慎保留现有功能。

默认解释：平台导出数量不受五槽限制；五槽允许逐槽替换，不要求填满。已装入的胶卷重启、换卡、删除胶卷库文件后仍可使用。只在明确确认后提交，浏览和取消不修改槽位。

## 当前代码核查

- 基线 HEAD 为 21b4247。工作区已有独立的 800T 重建设计草案，本任务不修改它。
- native/gr3/m10v_library.h 保留 65 个历史胶卷 ID，五个槽位；当前菜单仅开放 33 款精选胶卷。导出以平台实际可选目录为准，不能把历史 ID 都当成当前公开产品。
- m10v_library_menu.c 和 gr3-m10v-native-build.mjs 已将 count/index 挂钩限制在 ImageControlController；全局原厂模型接口留给 ADJ。继续保持这个边界。
- 当前持久化是 64 字节 M10V2A/B 内部记录，保存胶卷 ID 及各槽效果参数，不保存外部配方；仅写入外部 ID 不足以实现独立 SD 胶卷。
- m10v_debug.c 使用原厂 SD 管理器 0x535847d8、对象成员 [5]、vtable [7/8/9/10] 打开/关闭/读/写文件。目前固定传输 4096 字节，必须重新核实读取长度、EOF、seek、卡状态、线程约束及失败语义。
- 内部 AppData 管理器为 0x53828014；读写入口 0x53825648 / 0x53825fa8。现有双记录和回读校验可参考，但大记录容量及断电语义不能假定与 64 字节相同。
- 旧 GRLife 外部库已废弃，不恢复旧路由和公钥替换方案。
- 现有 native 构建有来源哈希、原指令断言、分区差异及 512 KiB 模块预算检查。新功能继续使用这些约束，不为了过构建而放宽预算。

这些是源码核查结果，不是本次新增的 ARM 执行证据或真机验证。参考网页本轮 web 工具无法打开，交互分析以用户提供的四张截图为依据。

## 方案比较

1. 推荐：自有 SD 配方包 + 按需读取 + 五槽完整配方持久化。可独立更新卡上胶卷，加载后不依赖卡上旧文件；需要验证存储容量及事务写入。
2. SD 只保存内置胶卷 ID 清单。开发量小，但新配方必须重新刷固件，不符合长期外部胶卷库目标。
3. 拍摄时从 SD 读取配方。节省持久化空间，但拔卡、坏文件和拍摄时序会影响成像，不采用。

## 推荐设计

### 平台与文件

增加 SD 胶卷库导出入口，与固件构建分开。提供全选、清空、多选、数量和体积，零项时不导出。以现有平台目录生成实际配方与原有图标，不把不可执行的配方静默替换成默认卷。

拟定路径 SD:/M10V/FILMS.M10。自有版本化、只含数据的格式，包含机型/运行时能力、目录、稳定卷 ID、名称、分组、色彩数据、效果能力和图标。每项有长度及校验，记录配方版本与内容摘要；不包含地址、可执行代码、指针或任意路径。格式最终数值布局须在原厂 IO 及存储约束核查后锁定。

数量限制来自包大小、地址算术及可支持索引范围，不来自五槽。不得宣称物理无限容量；实现必须披露明确上限并覆盖当前平台全部目录。按页读取目录，按需读一卷，不把全库加载进 RAM。

### 机内入口与操作

在已隔离的主菜单路径显示“胶卷库”（英文环境对应 Film Library）；保留 ADJ 原厂编号范围。先选活动槽，再进入 SD 胶卷列表，显示名称、分组和页码，支持逐页浏览、确认、取消。中文文案需核对原厂字库，不能仅替换 UTF16 字符就宣称设备可显示。

优先复用已验证的原厂列表和按键分发，先完成可靠选择功能；截图中的横向胶片带仅作交互参考，不作为必须重写整个渲染器的要求。不得把私有菜单 ID 交给原厂 tone setter。

### 装入和持久化

读取并验证目标完整配方到临时缓冲；检查兼容性、长度、算术边界及校验。准备新槽快照，写入非活动持久化记录，回读验证，通过后发布新状态。失败保持原槽和全部其他设置。完整配方持久化容量与原子性验证是实施前置条件，未验证前不生成可刷候选。

v2 槽 ID 迁移为其对应的完整配方，保留颗粒、柔光、800T 参数和时间戳配置。新槽存储需独立版本及文件名，不覆盖旧记录，以保留回退依据。槽位图标与名称必须和已提交配方一起变更。

拍摄只使用已验证的槽数据，不读 SD、不解析包、不写配置。新增选择路径不改变当前成像算法；新增配方若需要当前引擎不支持的能力，明确拒绝。平台预览与实际 JPEG 色彩的差异单独记录，不声称 ISP 与 JPEG 后处理等价。

### 故障边界

无卡、文件缺失、空库、截断、错误机型/版本、超大数量、重复 ID、坏校验、短读、拔卡和存储失败必须返回明确状态，不写原厂配置、不覆盖已装配方。所有打开句柄与临时内存有确定的释放路径。对 SD 服务的阻塞/线程要求以原厂调用链分析为依据，不能用重试循环掩盖问题。

## 实施与验证顺序

1. 从匹配 GR III 2.10 原厂固件核对 SD 文件服务和内部持久化 ABI，记录调用链与真实指令探针，明确替身边界。
2. 锁定自有文件格式与跨 Node/C 测试向量；验证截断、溢出、错误索引、损坏及不支持能力均安全拒绝。
3. 加入平台选择导出、独立包审计及解压安装说明；保留现有构建路径。
4. 加入固件按页读取、五槽事务、迁移和菜单；回归 ADJ/main/detail 的确认取消、原厂 tone 写入、拍摄链与组合功能。
5. 对实际 ARM 模块执行相同测试向量，再独立解码最终固件，核对所有改动地址、未修改分区、校验和、预算和来源清单。
6. 真机分阶段验收：打开/取消菜单、全量目录首尾、逐槽替换、重启和换卡、保存失败、JPEG/RAW+JPEG、连拍、颗粒/柔光/时间戳/800T、画幅/水平仪/原厂负片颗粒。

离线验证只能产出待实机验证候选。本任务不自动写卡、刷机或上线；已授权的本地研发在设计阶段门槛通过后继续。GR IIIx 不自动套用本轮 GR III 地址与结论。
