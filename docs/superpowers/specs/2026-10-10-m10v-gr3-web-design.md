# m10v GR III 本地固件工作台设计

## 目标与边界

m10v 是仅在用户电脑运行、由本机浏览器访问的 GR III 固件分析与制作工作台。首批目标功能为自定义裁切比例和关机画面。稳定性优先于功能进度；工具不连接相机、不自动刷写，也不把离线校验解释为实机安全。

首期交付只开放官方固件识别、分区与版本报告、电脑端原厂 BIN 备份、备份校验和恢复演练。裁切与关机功能可以展示研究进度、设计预览和阻断原因；在各自证据门禁通过前，不得导出声称可刷写的修改 BIN。未来候选构建属于后续独立阶段，须重新审查和验收。

## 输入基线与现有证据

唯一接受为官方基线的文件是用户提供的 `fwdc239b.bin`，长度 30,391,780 字节，SHA-256 `d6a3c9c288d784080e7b283222ecdd8752adfeed6faa36dab44f73115354bfd4`。只读解析识别 GR III、项目号 588、内部版本 `2.10.21.27`、14 个分区，容器和分区校验通过。公开版本为 2.10。相同文件名或版本号不足以证明输入身份。

参考项目 `gr-custom-tool` 的 GR4 页面与流程，以及已有的 GR III 精确基线解析和备份核心；不移植 GR4 的固定地址、版本族、尾部元数据、裁切或关机补丁。若复用其 GPL-2.0-only 代码，m10v 的源码许可与第三方声明必须满足该许可。

当前未证明 GR III 的可写 CPU 校验修复字段、修改候选的实机启动结果及相机端恢复路径。服务端因此必须拒绝相关构建请求，不能通过页面开关、用户确认或修改项目记录绕过。

## 架构

- Node.js 本地后端仅监听 `127.0.0.1`，负责文件接收、严格解析、备份、验证、状态与审计。启动时使用随机端口和会话令牌；所有改变本地状态的接口校验令牌与来源。macOS 可双击 `start.command`，也可用 `npm start`；Web 使用不依赖 Python。
- 浏览器前端负责导入、报告、备份及功能工作台；不自行判断固件是否可生成。页面从后端读取能力和阻断原因。
- 固件解析与备份核心独立于 HTTP 层，测试可以直接调用。原厂 BIN 以内容哈希命名保存在应用数据目录，创建后只读，不在 Git 中提交，也不随源码或页面资源提供。
- 后续候选管线独立于首期 API：补丁计划、预期原字节、重建、独立重解析、逻辑和物理差异、精确基线还原、审计清单、原子发布。缺少任何强制证据时，结果只保存诊断，不进入下载目录。

## 用户流程

1. 用户在本机启动 m10v，浏览器打开本地地址。首页显示当前允许的能力与相机写入状态。
2. 用户选择 BIN；服务端计算长度和完整 SHA-256，再校验机型、容器、分区顺序、长度、校验和与组件版本。失败时显示具体阶段和原因，不建立可编辑项目。
3. 成功后展示官方身份、完整哈希、内部版本、公开版本、各分区大小及哈希、校验结果和未验证事项。
4. 用户可导出备份 ZIP，并在全新本地数据目录导入演练。演练后重新计算原厂 BIN 哈希并核对项目清单，生成可保存的恢复报告。
5. 裁切和关机工作台分别展示 `unsupported`、`offline_verified`、`hardware_testing`、`hardware_verified` 或 `failed` 状态、证据和阻断原因。普通用户流程中，仅硬件已验证的能力才可默认开放候选导出。

页面分别命名“恢复 m10v 项目”和“相机固件恢复”。前者只恢复电脑端文件，不能表示相机 Flash/NAND 已备份或能够修复刷写失败。

## 备份契约

备份 ZIP 包含精确原厂 BIN、项目数据、用户素材、已登记的构建报告和说明文件。清单记录每个成员的相对路径、字节长度和 SHA-256。导入前拒绝路径穿越、符号链接、重复名称、额外或缺失成员、超限文件、无效 JSON、哈希不符及未知官方输入。全部验证在隔离临时目录完成；写入采用原子发布，失败不得覆盖现有项目或原厂备份。

备份恢复演练必须使用新的本地数据目录，重新解析原厂 BIN、核对清单和完整哈希，并确认已登记项目可读取。导出包不包含相机内部 Flash/NAND 的镜像。

## 版本与回退研究

版本候选仅能在已证实的 `2.10.21.x` 内部版本族中单调递增，检查已占用值和四字节上限；不能自动进位或借用 GR4 的 `1.11.10.x` 规则。任何版本变更必须证明所有实际版本字段、必要校验修复、非目标区域不变及逆向还原到精确官方 BIN。

提高版本号仅是待检验的研究方向，不能被描述为已证明可绕过相机的降级限制。原厂 BIN 的电脑端备份也不能保证相机接受旧版本或在刷写故障后可恢复。最小版本候选必须先通过单独的离线审核，再由用户基于明确的相机端恢复条件决定是否进行实机实验；在此之前，页面不提供回退候选。

## 裁切与关机功能门禁

两项功能分别建立布局证据、原始字节断言、修改计划、生成后回读、差异报告和实机记录，不共用通过状态。未知地址不能由 GR4 偏移推断。任何可执行代码修改还需独立证明指令模式与边界、可达路径和跳转范围。

首期可以展示功能需求和静态预览，但预览不可伪装成已写入固件。后续每项功能先做最小候选，按独立测试清单验证拍摄、存储、回放、关机、重启与设置保持，再考虑完整编辑流程。

## 界面与交付顺序

先制作首页、固件报告、备份恢复、功能工作台的渲染图供用户确认，再写页面代码。界面应清楚区分已验证事实、推断和未验证步骤；风险提示与实际按钮状态保持一致。首期完成后再立项候选构建和每项功能适配，不用占位按钮暗示可用。

## 验收

- 精确官方样本可导入并得到一致的长度、哈希、版本、分区与校验报告；变造一字节、错误机型或损坏帧均被拒绝。
- 原厂 BIN 备份导出、清单验证和全新目录恢复演练通过；损坏、篡改或路径攻击的 ZIP 被拒绝且旧项目保持可用。
- 仅回环地址可访问本地服务；状态写入接口需要有效会话凭据。
- 前端与直接 HTTP 请求均无法在门禁关闭时取得修改 BIN；裁切与关机的状态相互独立。
- 源码与构建包不包含用户提供的官方 BIN；文档明确区分离线验证、电脑端恢复和相机端恢复。
