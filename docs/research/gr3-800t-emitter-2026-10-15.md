# 800T 点光源识别与红晕收敛

目标：以用户的 5219 除碳胶卷实拍为视觉参考，减少夜景桥索、桥面等反射高光泛红，让红晕集中在灯光周围。未拟合胶卷扫描色彩，不把单张照片当作物理标定。

当前原生胶卷库使用 bit31 参数接口。该路径在原有高光遮罩上加入局部二维峰值判断，继续使用既有 gain/spread/threshold/profile 档位与状态格式。旧 control0/1/2 接口保留已有渲染，避免改变旧适配器的约定。

识别步骤：

1. 候选核心必须高于所选亮度阈值至少 8 级。默认 threshold5 的阈值为238，核心最低为246；降低阈值可纳入更暗的灯。
2. 在归一化网格半径1、2、4处扫描矩形边界，比较核心与各有效侧最大亮度。横向和纵向必须都有可用侧；每个有效侧均应低于核心。扫描完整边界可抑制倾斜亮线，而不是仅靠几个方向采样。
3. 采用最佳尺度的核心对比度作为光晕种子，抑制弱峰。缺失的画面外侧不参与判断，保留被裁切的角灯、边灯。
4. 后续保留高光中心保护、宽高光连通区域排除及亮度/红色散射合成。当前参数路径对模糊遮罩 a<8 的弱尾部采用 sqrt(a*255)*a/8 渐弱，a>=8 保留根号幅度，恢复近灯红晕。

不能用对向两边的平均值做核心判断：一明一暗的亮线端点和白墙四角也会得到约一半核心强度，且局部分类后大亮块被切断，绕过连接区域排除。新增测试覆盖这些反例，而不仅检查线条中段。

验证：真实 C 代码执行覆盖水平/斜桥索、桥面、线端、白墙角、无高亮核心反光、点灯、被裁切的灯、参数、粒子、边界及 scratch canary。ARM 与 host 输出一致，调用寄存器/标志位/栈保持。独立 ARM 核心为4096字节（4096预算），无新增外部函数、分配、I/O或状态字段。通过既有 lock_gr3_800t_code.py 刷新审查后的核心字节与源码指纹，独立回读检查仍严格校验。

预览在 `builds/800t-emitter-optimization/`，包括原版核心、可复现脚本、两张照片的 INPUT/BEFORE/AFTER、完整尺寸 PNG、红色增量图和 simulation.json。均实际调用当前 m10v_library_render，参数固定3/3/5/自然，关闭颗粒、柔光、时间戳。RGB成片经软件YCbCr422转换，不能代表相机ISP精确输出。第二张本已有胶片红晕，因此结果保留并叠加于已有成片；前一张数码照片更适合比较新增光晕。

首轮较弱预览在两张给定照片中，输出相对于同色彩处理但关闭光晕的正向RGB红通道增量总和分别降低约89%、91%；这是该软件预览的统计，不是对胶卷相似度或所有场景的性能保证。

能力边界：相同像素结构的饱和点状反射与灯无法可靠区分；低于阈值的灯和宽大均匀发光面可能漏检；没有二维上下文的单行/单列网格不产生该路径的光晕。仍需在GR III上检查最终观感与处理耗时。

后续用户反馈：点灯与灯带应增强，大面积光源应压制。补充极亮窄灯带通路：仅最小两个网格半径1/2、核心遮罩>=192时，允许一个轴方向持续明亮，但另一个轴的两侧必须回落；默认对应核心Y>=254。横/竖窄灯带回归有红晕，饱和宽桥面、白墙、贴画面边缘亮块保持中性。灯芯保留白色，红晕与亮度提升集中在周围。该规则不是语义识别：同样饱和的窄反光可能入选，斜向均匀灯带和较暗灯带仍可能漏检。

最新预览在 builds/800t-lamp-presence/digital/after.png，lamp-crops.jpg 对比关闭光晕、上一轮偏弱版本与新版本。真实 C 管线默认3/3/5/自然不变；当前数码桥照片的正向RGB红通道增量总和比原始泛红版本低约47%，不将该统计视为观感标定或硬件结果。

两像素灯带增加横/竖、网格offset0/1回归，修复移动一个像素后完全漏检；粗网格maxpool仍有强度相位差。宽亮面局部窄尖端也可能被归为灯带，不能声称所有大光源均完全排除。
