# GR III 机内胶卷卡片界面

按用户确认的参考样式，胶卷设置页和胶卷选择页保留一屏五卷，改用 120×196 彩色胶卷卡片、竖排大字片名、上下齿孔与黄色选中框。完整片名仍在卡片下方显示，按键、安装与保存逻辑不变。

40×40 紧凑图标（671–738）保持原样；仅上述独立页面使用五个运行时卡片资源（739–743）。这些资源的描述符初始为空，胶卷视图首次绘制时申请一个 470400 字节的五卡片缓冲区，翻页复用，销毁时清空描述符并释放。时间水印页不申请卡片内存。分配失败时安全回退到原有紧凑图标。

大图由本项目 C 绘图器按目录生成，不增加 68 份大位图、不改 ICONBIN 分区，也不扩大既有运行时预算。生成的卷标数据和源码参与构建校验与来源指纹。资源描述符是专用的 40 字节可变运行时数据，其余资源仍只读使用。

可用以下命令重新生成预览：

```sh
.venv/bin/python scripts/preview_gr3_film_cards.py
```

预览保存于 `docs/previews/film-ui/`，卡片像素来自实际 ARM 绘图代码，位置取自原厂构造函数创建的实际视图对象。标题、片名与底部提示使用宿主字体替代，故这是离线布局和资源预览，不是真机屏幕截图。最终字体、显示性能与机身内存可用性仍需真机验收。本次未部署服务、写卡或刷机。

## 本轮验证

- 菜单、控制器、选片、保存与旧图标的 72 项 ARM 回归通过。新绘图器和最终视图的 11 项检查通过，涵盖全部 68 款胶卷的像素边界、RGBA 色序、异常输入、分配失败回退、翻页复用和真实链接描述符释放（两组含重叠用例）。
- `0x540b6000`、`0x540ba000` 两个运行时基址均执行了实际视图创建、绘制和释放检查。
- 最终 SD 胶卷库运行时为 598648 字节；官方固件候选通过独立构建与回读，只改变 RTOS，仍标记 `camera_tested=false`。
- Node 全量 258 项中，初次运行 251 项通过、4 项跳过；两项因测试期间源码变化触发的来源指纹校验失败，在固定源码后复测通过。原网页五槽位与水印导出流程、RAW NR 集成导出流程均通过。另有一项可选的全部扩展组合矩阵在单独串行复测时仍超过其 180 秒限制，保留为超时，未报告全量通过。
