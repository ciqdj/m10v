## 已复现的截图方案

用户的 GRLife 修改包包含五个功能：配方、时间戳、画幅比例、胶片模拟和滑轨水平仪。Custom1 的机内名为 `Leica`，参数为 `[2,0,-2,1,1,1,1,-1,2]`；Custom2 名为 `Koda`，参数为 `[-4,4,1,4,-4,3,1,2,2]`。两个位置保留原厂图标。胶片为 Ektar 100、Gold 200、Pro 400H、Portra 400、Vision3 250D。

用本机缓存的 GRLife 公开 Python 浏览器核心处理官方样本与这份方案，生成的 BIN 与用户提供的修改包**逐字节相等**。m10v 另用自身解码器检查容器、14 个分区、分区校验和及输出差异。两个样本的变化落在 RTOS 和 ICONBIN；RTOS 解码体增加 27,200 字节，其他分区内容保持一致。五个机内胶片图标是实际的 40×40 RGBA 像素，而非网页装饰图。

## 胶片与配方边界

- 配方的九项值为相机原生 `-4..+4` 参数，不等同于网页的图像滤镜。机内名称限制 11 个英文字符；Cross Processing 位置被胶片功能占用时不可再放配方。
- 胶片替换五个原厂风格。目录现有 32 款；选择器优先保留各胶片的原槽位，再按机内名称空间分配。非原槽位的目录胶片会写入真实 Q13/Q9 矩阵、256 点曲线或第五槽的 33 点结点以及 RGBA 图标。
- 自定义 sRGB `.cube` 先经公开 GRLife 拟合算法转换为相机可表达的两组结果，并显示预计色差。网页前后对比只近似使用导出的矩阵和曲线，不能模拟相机 ISP、镜头、曝光或最终 JPEG。
- 兼容运行时、胶片拟合模块由 `scripts/sync-grlife-runtime.mjs` 依据固定 SHA-256 同步到忽略目录 `.runtime/`。项目没有把 GRLife 第三方源代码收进 Git；公共来源有变化时需重新审查哈希、行为和许可。

## 验证范围

1. 截图方案：官方样本 → 本机预检 → 构建 → 独立回读 → 与用户 GRLife 输出 `cmp` 相等。
2. 目录换选：哈苏 `HB HNCS` 替换 Ektar 后，预检与构建通过独立回读。
3. 自定义 LUT：恒等 `.cube` 拟合为两组数值表；作为第五款胶片构建并通过独立回读。
4. 以上均为电脑端结果；**未在 GR III 上刷写、启动、拍摄或验证恢复**。无法承诺刷机后 100% 复刻，也无法凭离线校验保证刷写安全。
