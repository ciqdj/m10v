### RTOS 指令与数据交叉引用

- RTOS 启动复制记录把 ROM `0x5407B540` 起的初始化数据复制到 RAM `0x55000000`，长度 `0x3A080`。因此 RTOS 文件偏移 `0x107E0B8` 对应 RAM 表 `0x55002B78`。

### 更新版本比较的局部代码

RTOS 中存在 `Update Version is older than Current Version!!` 字符串（偏移 `0xD33804`）。在 `0x536284E0` 开始的 ARM 函数中：

- `0x536298F8` 从候选包外层偏移 `0x38` 读取版本字节；`0x53629008` 从候选 CPU 载荷偏移 `0x90` 读取版本字节。
- `0x53628574` 比较候选与当前版本，`0x53628578` 的 `BLO` 在候选较低时跳向诊断/失败路径；另一组比较在 `0x536285D4`，`0x536285D8` 的 `BHS` 在候选大于或等于当前值时继续检查。
- `0x53628524..0x5362854C` 按结构体 `+0x2C` 的类型值分派：0/1 走外层版本解析，2/3/4 走双版本比较，5 直接走此函数的成功路径，6 走 CPU 版本解析。外层分支另在 `0x5362862C`、双版本第二项在 `0x53628644` 执行 `BLO`。类型 5 不比较版本仅是**这个函数的局部事实**，不能据此制造“免版本分区”：分区类型、内容和其它验证仍由更新程序约束。
- 失败路径 `0x536285DC`/`0x536285E4` 装载上述诊断字符串地址，`0x536285FC` 返回 0。
- 上层更新状态代码在 `0x53838CD0` 调用该函数，`0x53838CD4` 检查返回值，`0x53838CD8` 在返回 0 时转入错误分支。因此，修改**待刷包内**的 `BLO` 指令不能影响这一次更新：比较由相机当前运行的代码先执行，待刷 RTOS 尚未安装。

因此，**这一个版本门禁**确有“较低版本拒绝”的指令证据；相等版本不会因上述严格小于比较而失败。它并不证明更新程序整体允许同版本重刷，更不证明改版本号、修改 JPEG 或改裁切代码后能通过其它完整性/硬件门禁。完整更新调用链与接受结果尚未验证。

`scripts/analyze_gr3_update.mjs` 现将可逐字节复验的局部更新证据列为矩阵：`0x53838CD0` 为更新状态对版本门禁的调用与失败分支，`0x53628574` 为严格低版本比较，`0x536290C8` 是项目/标记处理包装函数的入口，`0x53629044` 是 CPU 校验函数入口。后两个入口的**完整调用条件和返回值消费**仍未连通到刷写回调；矩阵明确标记 `flash_write_callback`、`same_version_acceptance`、`full_project_marker_call_chain`、`CPU_verifier_call_conditions` 和 `recovery_path` 为未解决项。这些地址只支撑局部代码事实，不能由函数入口推断整包会被相机接受。

### CPU 分区加和校验

CPU 载荷为 `0x20000` 字节。`0x53629044` 起的 ARM 函数读取其头部 `0x7C..0x7F`；当该字不为 `0xFFFFFFFF` 时，逐个读取并累加整个 `0x20000` 字节范围的大端 32 位字，末尾 `CLZ` 检查加和是否为 0。官方样本中 `0x7C` 的大端字为 `0x93800936`，恰好等于其它所有 CPU 字的加和补数，完整加和为 0。`0xFFFFFFFF` 在**这个函数**中走返回 1 的特殊分支；这不是可采用的绕过方案，因为其它调用条件和整条更新验收链未证明。若修改 CPU 内的版本字段 `0x90`，仅修改字节而不修复 `0x7C` 会破坏官方样本所用的校验。该函数在相机更新链的具体调用条件仍需继续追踪。

外层容器和整个解码区另有小端 32 位加和校验。它们与 CPU 分区校验是不同层级；修复其中一层不能替代其它层级，也不能证明不存在其它验收条件。

## 裁切

当前工作台仅计算输入比例的画幅形状。虽已定位一个比例命令接口，GR III 的菜单身份、主图尺寸函数、DNG/RAW 窗口、回放解释、设置持久化及其可执行代码模式仍未独立证明。GR4 的裁切实现不能直接移植。

`StillAspectRatio` 字符串位于 RTOS 偏移 `0xB27D98`。已沿命令分发表定位到写处理函数 `0x53307464` 与读处理函数 `0x53366B64`：写端将文本 `3_2` 映射为内部值 0、`1_1` 映射为 3，再调用 `0x532525A4`；其它文本进入无效参数路径。该设置函数在 `0x532525C0` 将值写入上下文 `+0x4C2` 的一个字节。读端调用 `0x53245260` 从同一字节读取，仅将 0 和 3 格式化为上述两种文本。`StillCropMag` 则在另一个命令处理函数中被解析为浮点值，不能据此把它等同于任意裁切比例。

上述是**命令接口和状态字段**的证据，尚非完整拍摄链：同一区域还可见 `1:1`、`3:2`、`4:3` 文本，但菜单可选项、JPEG 主图尺寸、DNG/RAW 窗口、预览框、回放和保存后的解释路径尚未逐一追踪。直接扩充命令字符串或改写 `+0x4C2` 字节不足以实现可靠的自定义比例。
