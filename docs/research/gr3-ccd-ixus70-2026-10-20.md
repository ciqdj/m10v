# CCD Classic: IXUS 70 colour interpretation (2026-10-20)

The existing ID 72 and name `CCD Classic` now use a Canon DIGITAL IXUS 70 /
PowerShot SD1000 (2007) daylight-colour interpretation. This replaces the
previous generic GR DIGITAL-inspired contrast/saturation model. It is an
independently authored display look, not a measured or manufacturer-supplied
camera transform. No camera calibration or hardware pixel equivalence is claimed.

## Evidence and asset provenance

- [Canon official support and original manual listing](https://www.usa.canon.com/support/p/powershot-sd1000)
  establish the SD1000 / DIGITAL IXUS 70 naming correspondence.
- [Canon's original product catalogue](https://downloads.canon.com/cpr/software/camera/FULL_LINE_0113W698.pdf)
  documents Vivid Red/Green/Blue, Positive Film, and skin-tone controls. It
  provides no numerical camera transform.
- [Imaging Resource's original-camera test](https://www.imaging-resource.com/cameras/canon-sd1000-review/)
  describes stronger red, modest blue/green saturation, warm skin, cyan moving
  toward blue, and some red moving toward orange. These observations motivate
  selective colour directions; no chart measurements or coefficients were extracted.
- [PhotographyBLOG's original full-size sample JPEGs](https://www.photographyblog.com/pages/reviews/reviews_canon_digital_ixus_70_3.php)
  are a visual reference, not paired GR III calibration data. Images were not
  copied or redistributed. No open redistribution licence was verified for the
  referenced manuals, reviews or sample photographs.
- [OKLab author's colour-space description](https://bottosson.github.io/posts/oklab/)
  supplies the published mathematical transform. The author explicitly offers the linear-sRGB example under public domain
  or MIT terms. We use the public-domain mathematical constants and an independently
  written NumPy implementation. No third-party camera profile, LUT, photograph or software code is bundled.

The numerical settings below are all design assumptions. The yellow-green
refinement and gentler highlight tonality are deliberate aesthetic adaptations
for the user's nostalgia preference, not observations measured from SD1000 output.
The old camera is digital too; LUT colour cannot reproduce its lens, sensor noise,
flash lighting, resolution, sharpening, dynamic exposure or subject rendering.

## Domain and model

Input and output are bounded, encoded display sRGB D65 after the existing ISP.
Decode sRGB, convert linear sRGB to OKLab, adjust perceptual lightness and OKLCh
hue/chroma, map back to sRGB. Raw camera DCP/ColorMatrix values are not used:
those describe camera-native raw colour and cannot be applied directly to JPEG.

Periodic cubic splines connect colour anchors without hue seams. A cubic
smoothstep removes hue changes near neutrals (`C=.015` to `.06`). Chroma gain
fades out from `L=.85` to `1`. A monotone PCHIP lightness curve preserves black
and white. Exactly neutral source ramps remain exactly neutral.

Gamut mapping finds the linear-sRGB boundary at constant perceptual lightness
and hue by bisection, then uses an exponential chroma shoulder near that boundary.
The final numerical clamp handles roundoff; it is not the primary gamut mapper.
All of this runs only in the offline generator. The shipped LUT remains 15 cubed,
8-bit RGB, blue varying fastest, with tetrahedral interpolation. Native ISP
profiles still use the existing matrices, curves and twelve hue sectors. No new
runtime pass, grain, halation, blur or texture is introduced.

## Verification scope

Tests compare actual selective hue directions, restrained skin colour, neutral
ramps, finite/bounded and locally smooth colours, browser alpha preservation and
source-buffer immutability. The native clean fast path still leaves image buffers
untouched when native colour was completed and no spatial effect is requested.

Interpolation error compares the analytic interpretation with its quantized 15³
LUT. Native fit error compares the extracted Standard-gamma mathematical model
with that LUT. Neither is error against a physical Canon or Ricoh camera. Random
RGB-cube samples are not a natural-image distribution. Real-camera comparison is
still required, including skin, daylight sky, foliage and mixed artificial light.

## Generated target-fit results

- Analytic interpretation → 15³ LUT: ΔE00 P95 0.4698.
- LUT → quantized native model, 8,192 independent uniform RGB holdouts: ΔE00 median 0.6246, P95 1.7795, maximum 4.2514.
- Initial stronger colour target exceeded the desired native-fit budget (median
  1.0120, P95 2.5358). Selective changes were reduced rather than accepting that
  approximation regression. A second candidate had P95 2.2923. Final numeric
  target-fit gates are median ≤ 1 and P95 ≤ 2, with interpolation P95 < .5.
- IDs 69–71 retain exactly their original LUT values, basic native profiles,
  full native profiles and table hashes. ID 72/name/default grain remain unchanged.

These are measured errors of software representations of an assumed target;
**they do not measure Canon similarity, physical GR III ISP accuracy or real-camera
visual quality**. No firmware installation or camera capture was performed.

Scoped verification passed: `tests.test_gr3_ccd_film` (6),
`tests.test_gr3_curated_films` + `tests.test_gr3_isp_native_look` (12), and
`node --test node/gr3-ccd-film.test.mjs` (3). The browser CCD test was updated from
its old hard S-curve highlight-brightening requirement to the new gentle shoulder
requirement; neutral endpoints, monotonicity and alpha assertions are retained.
