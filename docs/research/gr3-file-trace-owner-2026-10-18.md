# GR III installed synchronous file trace owner

The locked image is GR III 2.10 RTOS SHA256 `8a4eafcad2716e0b21e9909264e1242e534f0e39e05cba82a53546ceb4070b67`. `build_gr3_file_trace.py` produces four checked patch records plus executable ARM code. This complements the recipe-owned trace and connects actual save bridge callbacks to caller-owned diagnostics without asserting a RAW recipe identity.

The sole aligned direct caller of `534eb8b4` WriteStillFile is BL `534e8828` in outer function `534e8794`. Outer is itself called at `534e0f04`. Both use the original `mov ip,sp; push {...,fp,ip,lr,pc}; sub fp,ip,#4` frame layout. Consequently inner fp-0xc contains outer fp, and inner fp-4 contains saved return PC `534e882c`. The hook verifies that exact return PC before accessing outer state; foreign callers go directly to the original two-argument bridge.

The outer stack allocation at `534e87a4` changes from 24 to 34 hex, adding only 16 bytes. Original local accesses end at fp-3c; the extended SP is fp-5c. Three outgoing WriteStillFile stack arguments occupy fp-5c, fp-58 and fp-54. The new private pointer at fp-50 is disjoint from all those slots and the original locals. Epilogues restore SP from fp, so original incoming arguments, saved register slots and return behavior are unchanged.

At BL `534e8828`, a register/flags-preserving wrapper allocates an optional 656-byte trace from the stock allocator, initializes it, stores its pointer only in the outer frame, records wall-clock event 195, restores the original SP and arguments, then tail-branches to WriteStillFile. Allocation failure stores null and still executes the original save. Clock errors set the event status high bit and do not cancel saving.

The nested bridge BL `534eba44` is replaced with a same-callsite wrapper that reads this checked caller's owner pointer and calls the tested explicit four-argument save proxy. Its task identity is the original WriteStillFile r1 descriptor stored at outer fp-38. No trace record labels this value as a recipe or file number. The proxy executes original callback `534ec9b8`, including all supported status/event semantics, and returns the original synchronous result.

After WriteStillFile has executed its original cleanup and returned, outer BL `534e8834` ordinarily calls `534eb7e4`, whose entire body is `bx lr`. Its replacement preserves all original registers and NZCV, records event 196 with original result r5, clears the owner pointer, calls the explicitly linked `m10v_lifecycle_file_flush(trace)` sink, and frees the allocation. The callback performs no filesystem writes. A synchronous sink must finish consuming records before it returns.

The outer and its immediate caller contain no explicit filesystem mutex acquire/release. WriteStillFile waits for the original storage service before its cleanup and return. This places flushing outside the storage callback and after the local synchronous transaction. It does not prove the complete RTOS task's lock state, physical media durability, concurrency behavior or failure recovery on camera. The sink's filesystem safety remains an integration contract, and hardware validation is required.

Validation: `.venv/bin/python -m unittest tests.test_gr3_file_trace -v` passes four tests. Linked ARM execution covers actual original inner prologue and saved-fp linkage, all three outgoing arguments at their original call SP, pre/post r0-r12 and NZCV preservation, optional allocation and clock failure, synchronous flush-before-free and owner clearing, descriptor identity, and foreign-caller bypass with an intentionally unmapped outer pointer. Stock storage/allocator/clock boundaries are intercepted; these are CPU/ABI tests, not SD hardware tests.
