# GR III 拍后等待与连拍风险：2026-10-18

用户实机反馈：当前最新 M10V 固件，RAW+JPEG，800T、蓝凤凰、5207 拍后回放慢，连拍可能黑屏、漏存；原厂正片/负片较快。附件仅证明机身显示等待图标，不能提供线程、异常原因或文件写入状态。本轮没有连接相机、没有复现实体机黑屏或核对丢片文件。

## 从代码确认的阻塞点

`m10v_chain_capture` 在原厂 JPEG 编码提交调用 `0x536abd28` 前同步执行 `m10v_capture_library`。胶卷处理操作全尺寸 Y/CbCr422 平面，RAW CFA 不参与处理。800T 的能量提取、模糊、细光晕、合成和颜色处理，5207 的逐像素 LUT/颗粒，蓝凤凰的 LUT/颗粒/光晕都串在这里。原厂风格不调用这些 CPU 胶卷循环。

`m10v_camera_library_load` 每次拍摄读取双份 AppData 配置，尚未采用无 I/O 的拍摄快照。开启 debug 时还会在拍摄前后同步读取两页 4096 字节 SD 日志并写回另一页。日志 busy 位只能跳过重入，不能给底层文件服务提供超时。由此可以确定这些调用会阻塞保存路径，但不能在没有日志时认定它们就是黑屏或丢片的原因。

本轮保留同步处理与原厂编码器无条件接续。未在对象生命周期尚未证明的前提下加入异步处理，也未使用未经验证的 RAM 地址保存跨任务缓存。

## 修改

- `film_5207.c`：24 字节调用内颗粒格点缓存复用邻接采样；size=0 复用已有随机值。颜色/漏光模式每张图分派，漏光关闭时不执行漏光运算，LUT 路径不保留无用的原始 RGB 副本。
- `halation_energy.h`：模糊的内部像素使用直接邻接索引，垂直边界每行计算；800T 源能量全部为零时跳过对应模糊/合成。判定依据是舍入前的能量，保留微弱光源细光晕。
- 构建器仅对 library/5207/HARMAN 三个计算模块启用标量 `-O2`；菜单/ABI 仍用 `-Os`，不启用 NEON、硬浮点或额外线程。
- 同步生成 `m10v_sd_contract.h`。配方 SHA 绑定渲染源码，新固件换卷需使用重新导出的 `FILMS.M10`；已持久化槽位仍优先于固件初始值。
- 非调试候选不链接 SD 调试日志模块。不改变用户在机内保存的质感参数，不以关效果换取对照样本的提速。

## 已验证与限制

冻结修改前源文件，使用相同 6000×4000、stride6016、CbCr422 输入对照。800T、5207、蓝凤凰三张整帧的输出 SHA-256 分别锁定在 `tests/test_gr3_full_frame_render.py`，包括行尾填充。测试不声称穷举所有图像。

纹理使用冻结的旧 C 实现逐字节对照：color0..5、grain size0..2、漏光0/8、多尺寸、单行/部分行、所有漏光方向。光晕使用冻结旧 header 对照空红光源、空柔光源、只存在一种源，以及单点能量舍入到零的情况。独立 Python 模糊 oracle 检查窄边界及每次舍入。

同一 6000 像素宽、2 行暗输入的实际 ARM 指令工作量（不是相机延迟）：

| 默认胶卷 | 旧版指令/像素 | 优化后指令/像素 | 降幅 |
| --- | ---: | ---: | ---: |
| 800T | 153.98 | 69.87 | 54.6% |
| 5207 | 461.12 | 339.57 | 26.4% |
| 蓝凤凰 | 556.56 | 377.37 | 32.2% |

宽行用于验证颗粒在真实横向采样比例下的工作量；两行图像不能代表全高细光晕和全部缓存行为。另一次桌面混合明暗整帧对照中，耗时下降约 11% / 26% / 30%，输出相同。桌面时间与 ARM 指令数都不能转换成机身速度保证。

连续配方回归验证每帧释放 scratch、原始像素重新输入后输出一致、无配置写入。原有 ARM 回归检查 CFA 别名拒绝、配置/图像/临时缓冲区非重叠、分配失败时像素不变、寄存器/标志/栈恢复和原厂编码接续。顺序配方测试不能证明实体机并发、硬件 cache、文件系统时序、断电持久化或无限连拍稳定。

仍需实体机：同一 SD 卡、相同场景/曝光/格式，分别用原厂与新候选计时；逐款检查 JPEG+DNG 文件数量、文件可解码、内嵌预览和回放，再逐步增加连续拍摄数量。保留发生黑屏时的现象与文件证据，才能进一步归因。当前结论是减少已确认的保存前 CPU 开销，尚不能宣称黑屏或丢片已根治。

## 测试命令与产物

工作证据位于忽略目录 `builds/gr3-capture-performance/`。`baseline-*` 为旧源 ARM 测量，`host-full-frame.json` 为桌面整帧对照，`delivery/` 为非调试候选与配套胶卷包。沙箱内 Unicorn 的最小 `mem_map` 即触发 SIGILL；ARM 检查在沙箱外本地执行。HTTP 测试亦需要本机 loopback 监听权限。

```sh
.venv/bin/python -m unittest tests.test_gr3_capture_performance tests.test_gr3_texture_performance tests.test_gr3_halation_blur_work tests.test_gr3_full_frame_render
.venv/bin/python -m unittest tests.test_gr3_m10v_capture tests.test_gr3_m10v_library_arm tests.test_gr3_debug
npm test -- --test-concurrency=2
```

完整测试结果与最终固件摘要见 `builds/gr3-capture-performance/VALIDATION.md`。

Clang `-fstack-usage` 对照：纹理主函数 184→200 字节，`m10v_library_render` 368→368 字节；该数值是单函数静态栈帧，不能替代线程栈高水位或完整调用栈测量。候选代码与资源共 586,344 字节，低于已验证追加区 655,360 字节预算。
