# GR III 调试模式

在「保存固件」页面勾选「调试模式」后导出并刷入。默认关闭；当前仅支持 GR III 的 M10V 原生胶卷库方案。独立胶卷库导出页和命令行 `node scripts/export_gr3_m10v_native.mjs --debug` 也支持。调试选项参与预检摘要，修改开关后必须重新预检；网页保存流程自动完成预检。

复现黑屏、菜单或拍摄问题后，复制 SD 卡根目录存在的以下文件，并保留此次生成的 M10V-build-receipt.json。没有拍摄时可能只有菜单文件。

- M10VMN0.BIN、M10VMN1.BIN：菜单进入、按键、焦点切换、确认、重绘和设置保存。
- M10VCP0.BIN、M10VCP1.BIN：拍摄入口、渲染开始和结束、返回结果。

每个文件 4096 字节，四份共 16 KiB；每个通道循环保留最近 63 条事件。双页交替覆盖，CRC 校验识别写入中断或损坏，上一页保留上一有效检查点。跨通道没有统一时间戳，不能根据序号判断菜单与拍摄事件的先后顺序。记录包含阶段、调用参数、槽位/胶卷/菜单状态或返回结果、构建方案摘要前八位（含原厂包、配置、源码指纹和调试开关）。相同构建方案的后续运行续写，变更配置或模块源码则重置对应通道。

将文件解码为 JSON：

```sh
python3 scripts/read_gr3_debug_log.py /Volumes/SD/M10VMN0.BIN /Volumes/SD/M10VMN1.BIN /Volumes/SD/M10VCP0.BIN /Volumes/SD/M10VCP1.BIN > gr3-debug.json
```

参数只列实际存在的文件。解码器校验 CRC、页大小、格式、构建标识和通道，选取每通道最新有效页。如果最后只有某阶段的 before，没有 after，可缩小排查范围；突然断电、文件系统缓存或日志自身写入失败也可能使最后一条记录缺失，不能直接据此断定死机位置。

调试模式会增加 SD 卡读写，可能使菜单和拍摄变慢。无卡、内存分配失败或文件操作返回错误时放弃该条日志，继续原有流程；重入时跳过，菜单与拍摄共用原子守卫，避免两个日志写入互相等待；各通道文件和历史仍独立。原厂文件系统内部会等待同驱动锁，其他相机任务占用 SD 时仍可能等待，此实现无法保证单条日志的耗时上限。日志不记录图像，不增加相机设置文件字段。关闭调试重新导出的模块不包含日志函数和日志路径，也不写这些日志文件。已经存在的日志文件不会被普通固件删除。

已用真实编译的 ARM 代码及模拟 SD/堆验证环形覆盖、菜单与拍摄分离、写入中断回退、无卡/内存不足/重入，以及生成固件的完整模块回读。尚未在实体 GR III 验证 SD 实际落盘与异常关机行为。
