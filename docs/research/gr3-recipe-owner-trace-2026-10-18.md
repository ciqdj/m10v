# GR III recipe-owned lifecycle trace

Locked RTOS SHA256: `8a4eafcad2716e0b21e9909264e1242e534f0e39e05cba82a53546ceb4070b67`. This implementation emits installable checked patches, not a camera validation claim or a change to buffer ownership itself.

The only aligned ARM direct caller of `BEStillRecipe` constructor `5350f160` is `53523e1c`. Its factory sets size `4778` at `53523df4` and calls `5351091c` at `53523e0c`; that allocator passes the requested size to pool 7 vtable+8. Matching deletion `5351098c` passes the original object pointer to pool 7 vtable+c without a caller-supplied size. No guessed RAM or shared global owner is used.

The factory call is replaced with the same one-argument ABI. It requests `5070` bytes only for input size `4778`, zeroes the additional extent, and initializes a trace at recipe+4778. Failure returns the original allocator result unchanged; the stock assertion/failure policy still applies. The trace is 656 bytes (16-byte header plus 32 five-word records). Color snapshot storage is separately reserved at recipe+4a08 for 1640 bytes; it does not overlap the trace. The original 4778-byte object prefix is untouched by tail initialization.

`build_gr3_save_trace.build(out, base, rtos)` checks the full input SHA and every original instruction/table word. The manifest lists 13 patches: the unique factory BL, six existing BL calls to `535216d0`, five existing BL calls to `53521d14`, and recipe vtable+70 at `53d0fd00`. No original function entry is overwritten and no arbitrary instruction trampoline is needed. The original allocator, setter, buffer release, encoder and file service execute normally. Stock AAPCS caller-clobbered flags remain caller-clobbered; wrappers preserve r4-r11 and SP.

Events 187 and 183 retain recipe, old backing/source, new backing, and the actual stock caller LR. They distinguish the transfer target setter at LR `5351832c` and source clear at LR `53518360`, which can be paired by backing. This does not invent a target pointer from unrelated registers. Event 188 records allocator helper boolean return and policy, not an invented requested byte count; 186 and 189 bracket normal release. Source/backing addresses are values only; pixel data are never read by these hooks.

The RAM ring reserves six slots for phase events 190..198. Ordinary records stop at 25; phase records may grow the count to 31. `recipe_take` adds record 199 with the dropped count in its last reserved slot, then resets the ring. This prevents allocation/setter chatter from silently removing JPEG completion markers. Contended append/take returns immediately without spinning. A contended append cannot safely increment the locked dropped field and is omitted; this remains a diagnostic limit.

`m10v_save_trace_recipe_mark(recipe,event,a,b,c)` appends `(event,recipe,a,b,c)`. `m10v_save_trace_recipe_take(recipe,out,32)` copies at most 32 records into the current caller's RAM and clears the stored trace under a bounded try-lock. The module makes no filesystem calls. Production integration must call take and the existing batch logger only at the established capture worker boundaries; no allocator, setter, release or file callback writes SD.

The separate save bridge proxy remains a tested explicit caller-owned helper. It is not automatically patched into the stock two-argument bridge and does not claim that a file-write object maps to a particular RAW recipe. Camera runtime, ISP/SD scheduling and that final RAW-to-file association remain outside CPU tests.

Validation: `.venv/bin/python -m unittest tests.test_gr3_save_trace -v` passed five tests, including linked checked patch manifest, original ARM callback statuses, actual original RAW setter execution, extended allocation canaries and null result, foreign object bypass, AAPCS saved registers, ordinary overflow with all six phase records retained, and bounded drain. Unicorn requires elevated execution in this environment because sandbox execution can SIGILL.
