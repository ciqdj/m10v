# M10V GR III 机内胶卷库：官方固件基线与实现契约

目标机型是 GR III Street Edition 2.10，唯一输入是用户提供的 `fwdc239b-offical.bin`，SHA-256 为 `d6a3c9c288d784080e7b283222ecdd8752adfeed6faa36dab44f73115354bfd4`。用户实机反馈：旧外部胶卷文件方案的菜单存在，但点击胶卷条目没有反应。因此该方案已从产品入口移除，旧构建请求被拒绝，旧文件下载接口返回 410。历史代码和数据仅保留作问题记录，不作为新模块的代码或素材来源。

## 用户可见行为

固件内包含至少 33 套（含 800T）由 M10V 独立设计的胶卷色彩记录，不需要 SD 卡外部胶卷包、授权码或网络服务。相机菜单显示 **M10V 胶卷库**，可浏览胶卷、预览名称、选定五个活动插槽中的目标，并执行装入。当前候选连接保存的静态 JPEG 和重启后的五槽映射；取景和 RAW 再开发尚未接入。每个活动槽位可分别调颗粒和柔光的关闭、弱、中、强；JPEG 时间戳可独立开关并配置格式与位置。原厂固件恢复后，私有设置不得阻止相机加载原厂影像控制。

菜单和固件必须能辨认每一步失败：无可用槽位、设置写入失败、记录校验失败时显示错误并保持此前的五个活动槽位。不能出现可见菜单却没有动作反馈。候选 BIN 在用户实机验证以前只能标记为实验候选。

## 官方固件证据（本机重新读取）

原厂包完整 SHA 已重新核对；RTOS 解码体为 17,520,064 字节。本机从官方 RTOS 直接反汇编，`0x5324B338`、`0x5324B400`、`0x5324B4A4`、`0x5324B5B8`、`0x5324B6E0` 均以 `movw r1,#0xB28` 分配设置记录。`0x5323F274` 的保存入口通过 `0x53828014` 取得 AppData 对象并调用 `0x53826C54`，写入长度 `0xB26`。`0x535048E8` 的原厂捕获调用是 `bl 0x536ABD28`。官方资源含英文 `Grain Effect`、`Soft Monotone` 和 `HDF` 字符串；这些字符串仅证明资源存在，不证明普通 GR III 的柔光硬件或菜单可直接启用。上述地址全部只适用于此 SHA，不能据此声称已完成机内切换、持久化或 JPEG 质感处理。

## 架构选择

采用**固件内只读目录 + 五槽活动映射**。33 套（含 800T）记录使用 M10V 自定义格式编入 RTOS 扩展区，记录有稳定 ID、名称及原创 Y/CbCr 参数，整个模块由 SHA256 约束。颗粒与柔光初始值来自网页五槽配置。机内只保存五个活动 ID 与每槽覆盖档位；安装动作先验证记录，再原子替换活动映射。菜单从固件目录读取，不访问 SD 卡。这样既符合无外部包的产品要求，又避免旧方案的文件路径和签名依赖。

色彩记录的具体矩阵、曲线格式必须由原厂五个影像控制槽的消费者、RAW 显影和 EXIF 路径逐项反推；不能直接复用第三方目录中的 32 卷参数或图标。颗粒采用自有确定性亮度噪声。柔光如需 JPEG 空间扩散，则使用自有 ARM/C 内核，并在原厂 JPEG 描述符、缓存和 RAW 隔离证据齐备后接入。时间戳使用自有字体、布局与合成代码；它须与柔光共用一个经过验证的捕获入口，不能互相覆盖跳转。

## 导出门槛与实机验收

1. 从官方 BIN 单独确定影像控制菜单的选择回调、五槽映射、九项参数或色彩表、图标和名称读取者；用原厂 ARM 指令/数据引用与模拟执行交叉证明。
2. 确定内部设置存储的可用命名空间、完整写入/读回、校验失败回退和重置路径。不得仅因为主机可编码状态文件就宣称机内持久化。
3. 分别测试菜单浏览、选择、取消、装入和错误反馈；五槽切换后逐项核对 JPEG、RAW 显影、回放及 EXIF。独立回读候选的 ARM 代码、调用点、分区校验和及所有非目标字节。
4. 颗粒、柔光和时间戳分别进行单功能离线与实机验证，再测组合与高 ISO、JPEG-only、RAW+JPEG、连续拍摄和重启。用户测试机须能恢复官方包；电脑端校验不能替代实机结果。

截至 2026-10-14，原创 C/ARM 内核、33 套（含 800T）色彩、五槽菜单确认、内部双记录、颗粒、柔光和时间戳已连接；网页和 HTTP 本地构建已接入，可导出带实机未验证标识的候选。

## 已实现的链路与边界

`native/gr3/m10v_library*.c` 实现色彩、质感、日期、内部 FS、菜单和拍摄桥。44 字节状态使用 M10V0.bin / M10V1.bin 两份内部记录和 CRC32；写后回读成功才更新调用者状态。无外部胶卷包或授权码。

运行区 0x540B6000 只含代码/常量，临时数据在栈与已定位模型 padding。LLVM 脚本连接模块、75 条 UTF16 资源及网页初始记录。构建器核对 17 处原厂挂钩，重算容器校验；审计完整模块、初始值、非目标 RTOS 字节、其他分区及更新器/版本保护区。

原厂 FS、RTC、菜单、内存与缓存入口来自官方反汇编。ARM 测试明确模拟设备服务边界，不能据此证明原厂 GUI 和设备服务实机正常。

本候选是原厂成像后的静态 JPEG 色彩叠加，没有统一原厂各槽 ISP 基底。不宣称实测胶片标定、取景效果、RAW 再开发或 EXIF 显示原创卷名。已有机内有效 M10V 记录优先于网页初始值。

交付与实拍步骤见 `docs/testing/gr3-m10v-native-library.md`。


## 统一产品流程与 IIIx

首批两款机型共用导入、设置、保存三步。胶卷库直接挂载到影像设置 DOM，无独立来源状态或下载台。800T 作为第 33 条原创色彩记录，其私有菜单值 213 对应追加资源 860；原有胶卷、颗粒、柔光、时间戳资源 ID 不移动。原厂列表最大 33 条加 Back/Done 共 35 行。

红晕内核连接进原生模块，在原厂拍摄桥中与色彩、亮度柔光、颗粒及日期串联；先验证完整图像跨度、对齐与 scratch 隔离，再允许修改。运行模块限制 32 KiB，位于已验证的 0x540B6000–0x540BE000 可执行映射内。

IIIx 使用独立 SHA、版本、包头和项目标记检查。相同长度的 RTOS 仅有 31 字节差异；所有新模块引用的函数、对象布局锚点和资源表未变化。生成与审计从该机型自己的原包开始，不能把头部替换作为机型适配。


## v2 状态与目录统一

v2 的五槽各含 uint16 film、uint8 grain/soft/gain/spread/threshold/profile；总状态 64 字节，CRC32 覆盖前 60 字节。版本 2 新名称隔离旧记录，回读成功才原子更新调用者。加载失败不写默认；两份新记录均无效时校验并迁入旧 44 字节双记录。

目录 1–33 保留原 M10V ID，34–65 对应现有模拟目录的稳定顺序。矩阵/曲线/节点用有界差分编码无损内置，渲染前完整解码验证。RGB JPEG 路径明确区别于旧 ISP。页表检查针对实际模块结束地址验证 1 MiB section 映射、只读权限、可执行权限与 client domain，模块/表预算 60 KiB、RTOS 总增长限 64 KiB，非目标字节保护不变。

普通胶片模拟入口与胶卷库不再有不同五槽状态或不同颜色构建器。影像页通过同一个编辑器接口选卷，网页和菜单的光晕量化、档位映射及保存结构一致。
